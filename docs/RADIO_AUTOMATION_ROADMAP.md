# Radio 2.0 — дорожная карта профессиональной автоматизации вещания

Обновлено: 18.10.2026. Рабочий интерфейс — модуль «Радио» платформы MEDIA · РАФ · RAW; центр воспроизведения — один серверный playout, Windows Agent — основной аппаратный выход. Время сетки: Europe/Moscow (UTC+3).

## 1. Проверено в текущем коде, а не предполагается

| Функция | Текущий статус | Комментарий |
|---|---|---|
| Аудиотека, импорт MP3/WAV/OGG/FLAC/M4A | Есть | В существующем админском Radio API; размер загрузки ограничен 30 MiB |
| Плейлисты и папки, порядок элементов, длительность | Есть | Пока маршруты Radio закрыты ADMIN |
| Утверждение плейлистов | Частично | Сейчас админ утверждает любой плейлист независимо от автора; исправить |
| Сетка разовых передач и недельное повторение | Есть | Запрет пересечений, московское время |
| Dashboard радио и статус Worker | Есть | Развить в операторский пульт |
| Централизованный поток MP3 128 kbit/s | Пилот проверен | Worker воспроизводит утверждённые записи и тишину; реальный выход зависит от Agent |
| macOS Agent центральный эфир + локальный резерв | Пилот проверен | Пауза failover ~1–2 с приемлема для текущего этапа |
| Windows Agent и ESP32 | Отложено | Работать с физическим оборудованием 19.10.2026; до испытаний только наушники |
| Удалённый микрофон | Частично | Отдельный WebRTC-пилот, **не смешан** с основным MP3 |
| Контроль уровней, нормализация, cue/crossfade | Нет полноценной реализации | Следующая стадия |
| История реально воспроизведённого эфира и запись | Нет | Нужна для контроля сетки и аудита |
| Автоподбор музыкальных позиций и правила повторов | Нет | Следующая стадия |

Сведения о статусе — по текущим исходникам `server/src/routes/radio.js`, `server/src/routes/radioAgent.js`, `server/workers/radioPlayout.js`, `radio-agent/macos/`; требуют проверки на действующем сайте после каждого PR.

## 2. Референсы профессиональных систем

- mAirList: Automation/Live Assist, cue editor (ramp/fade), multitrack mix/segue editor, cartwall, time-fixed events, backtiming, voice tracking, playout logging; https://www.mairlist.com/en/products/radio-automation/
- mAirList: конфигурируемая студийная схема A/B decks, cartwall, библиотека; https://wiki.mairlist.com/tutorials:general:getting-started:v6_3:v6_3_playout
- RadioBOSS Cloud: repeat protection, exact/flexible start, per-type fades, silence trim, normalizing; https://www.radioboss.fm/support/radioboss-cloud/
- AzuraCast: приоритеты плейлистов, general rotation, расписание, live DJ/browser DJ, лог и управление станцией; https://azuracast.com/docs/user-guide/playlists/ и https://www.azuracast.com/docs/
- AzuraCast: переход между Live DJ и AutoDJ через единый движок; https://www.azuracast.com/docs/user-guide/streamers-and-djs/

Цель — не копировать интерфейсы сторонних продуктов, а выбрать лучшие рабочие подходы и визуально интегрировать их в собственный сайт.

## 3. Принцип редакционного утверждения плейлистов (обязательное правило)

**Администратор утверждает только плейлисты, созданные студентами.**

- Плейлист, созданный администратором: доступен для планирования без отдельного утверждения; решение фиксируется сервером автоматически. Никакой кнопки «Утвердить свой плейлист».
- Плейлист, созданный студентом: DRAFT → SUBMITTED → APPROVED или RETURNED; возврат обязательно с причиной. После существенного редактирования ранее отправленного/возвращённого плейлиста студент снова отправляет на рассмотрение. Кто, когда и почему изменил статус — в истории.
- Администратор может исправлять студенческие плейлисты, но должен явно видеть автора и причину; публикация изменений не должна втайне обходить процесс проверки.
- Механизм проверяет роль **автора**, а не роль пользователя, который сейчас открыл страницу. Серверные права — обязательны; одного скрытия кнопки недостаточно.
- Права: студент может читать библиотеку и управлять **только своими** плейлистами; админ управляет эфирной сеткой и решениями по студенческим заявкам. Утверждение себя или чужие записи через подмену запроса запрещено.
- Сетка выбирает только разрешённые для эфира плейлисты (администраторские авторазрешённые и утверждённые студенческие). Изменения запланированной передачи валидируются на конфликты.
- Уведомления: «Плейлист “…” отправлен», «Утверждён …», «Возвращён …: причина», с переходом в конкретный плейлист.
- До миграции убедиться в сохранении существующих `APPROVED` и расписаний, безопасно разграничить права и мигрировать историю без массового сброса статусов. Не делать неявную обратную смену уже эфирных плейлистов.

## 4. Ближайшая продуктовая разработка (без Windows Agent/ESP32)

### R1 — редактор плейлистов и модель согласования
- Роли и отправка на утверждение по правилу выше (API + БД + аудит + уведомления).
- Редактор плейлистов: перетаскивание песен, видимые зоны вставки, удержание для drag на телефоне, перестановка между плейлистами с явным подтверждением, множественный выбор. Никаких кнопок «вверх/вниз» как основного способа сортировки.
- Метаданные по строке: обложка, название/исполнитель, длительность, конец блока, статус файла, автор.
- Автосохранение с индикатором синхронизации; защита от конфликтующих правок двух редакторов; undo для drag.
- Быстрая фильтрация библиотеки по типу: музыка, джингл, подложка, рубрика, реклама.

### R2 — сетка вещания 2.0
- Дневной/недельный таймлайн по Москве; перетаскивание передач между слотами, растягивание границ **только** где правила допускают изменение длительности, drag-to-schedule из библиотеки, магнитная привязка к 5/15 минутам.
- Предупреждение о наложении, пустых интервалах и недостающих записях до публикации. Preview изменения до отправки.
- Правила точного старта (hard-time), мягкого старта по окончании трека (soft-time), приоритетов и пустых слотов.
- Шаблоны дня/недели, копирование сетки перетаскиванием, праздничные/исключительные даты.
- Защита от изменения уже проигранных интервалов и воспроизводимой истории сетки.

### R3 — эфирный пульт и мониторинг
- Единственный операторский экран: ON AIR/RESERVE/OFFLINE; текущая запись и таймкод; следующая композиция; индикаторы уровня звука, состояния серверного кодера и Windows Agent; сигнал о тишине; последние ошибки.
- Воспроизводимый журнал реально отданных аудиоблоков и смен источника с timestamp; диагностика разрывов; запись эфира (aircheck) с политикой хранения.
- Очередь эфира с drag-and-drop для санкционированных ручных перестановок без потери серверной синхронизации.
- Раздельные права оператора, редактора плейлистов и администратора.

### R4 — звуковой движок профессионального уровня
- Cue-in/out, intro/ramp, fade-in/out, музыкальные переходы/segue editor с waveform и прослушиванием.
- ReplayGain/EBU R128/LUFS и true-peak limiter, устранение пустоты в начале/конце, контроль клиппинга и silence detection.
- DJ voice tracking, музыкальные подложки и джинглы (cartwall), единый микшер для удалённого прямого эфира и автоматического вещания.
- Приоритет live → музыка → тишина/резерв; отдельный обязательный аппаратный аварийный приоритет, который никогда не обходится приложением.

### R5 — умная библиотека и автопланирование
- Автоматическое сканирование, анализ громкости и waveform, теги, обложки, категории/темп/жанр, обнаружение дублей по хешам и аудиосходству.
- Правила ротации: минимальный интервал между повторениями композиции/исполнителя, возраст/жанр/настроение, квоты типов контента; предварительный отчёт нарушений.
- Генерация плейлистов на основе часовых шаблонов и редакционная корректировка.

### R6 — эксплуатация и защита вещания
- Мониторинг CPU/FFmpeg/Windows Agent, ping и сквозная проверка аудио, предупреждения оператору по конкретным проблемам.
- Backups и безопасные релизы, журнал ошибок, ролевая модель, офлайн-кэш.
- Тестирование Windows Agent/ESP32/аварийной схемы только при физическом доступе, с отдельными критериями допуска к усилителю.

## 5. Интерфейс — обязательные правила

**Стиль:** те же цвета, прозрачные поверхности, радиусы, контраст и размеры кнопок, что во всей MEDIA · РАФ · RAW; полноценная светлая и тёмная темы. Никакого отдельного «чужого» интерфейса радио.

**Desktop:** компактный экран без дублирующего глобального header и без локального поиска; сверху узкая строка статуса, ниже основной контент. Плейлист: библиотека слева, очередь справа; сетка: календарь и инспектор выбранного блока; Dashboard: «сейчас/далее» и техника.

**Mobile / PWA:** одна колонка, закреплённый компактный ON AIR-бар, смена вкладок «Эфир / Сетка / Плейлисты / Библиотека». Вместо боковой панели — нижний выезжающий лист. Всё важное видно без горизонтальной прокрутки; крупные touch targets.

**Перемещение:** dnd-kit или совместимый механизм с Pointer + Touch + Keyboard sensors; drag handle, заметное место вставки, автоскролл, возврат при отмене и undo. Touch-drag через долгий тап/ручку, так чтобы обычный вертикальный скролл оставался нормальным. Accessible клавиатурная альтернатива допускается, но не отдельные кнопки вверх/вниз как основной UI.

**Операторская безопасность:** ручной drag не должен автоматически вызывать эфирное действие без авторизации и явного подтверждения там, где меняется уже активный плейлист/поток. Drag не заменяет авторизацию. Опасные/аппаратные команды из мобильной версии скрываются за отдельным подтверждением или недоступны.

## 6. Порядок PR

1. `radio/playlist-review`: модель ролей, административное автоподтверждение, студенческая подача, возврат с причиной, уведомления и тесты доступа.
2. `radio/playlist-editor-dnd`: мобильный и десктопный DnD-редактор и адаптивный UI.
3. `radio/schedule-v2`: drag&drop-сетка, проверки конфликтов, шаблоны.
4. `radio/onair-dashboard-v2`: компактный мониторинг, события, ошибки/тишина.
5. `radio/audio-quality`: анализ файлов, Cue/Mix, нормализация, переходы.
6. `radio/smart-rotation`: правила повторов и автоматизация составления плейлистов.
7. `radio/windows-esp32`: только после наличия устройств 19.10.2026; отдельные пилотные тесты, без подключения к PA до разрешающих проверок.

Каждый PR с серверными тестами прав и регрессии существующей сетки, мобильной проверкой iPhone/PWA и desktop, контрастом светлой/тёмной тем и проверкой безопасности эфира.
