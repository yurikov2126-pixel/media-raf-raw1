# Двухканальный ALARM: штатное завершение без STOP (PR #961)

## Исправлена логика окончания

Предыдущая версия `runMchsTwoChannelExecution` отправляла `STOP`
в оба канала даже после успешного естественного окончания ALARM.
Это смешивало штатную работу с аварийным восстановлением и требовало
лишних команд.

Для **изолированного учебного** двухканального сценария новый контракт:

1. Worker и Windows Agent получают одну и ту же учебную сессию.
2. Каждый подтверждает свой START с идентификатором события.
3. Исполнитель ожидает от обоих `waitUntilCompleted`.
4. Каждый ответ обязан содержать `completed=true`, совпадающий
   `eventId`, точное `repeats` и `reason='FILE_COMPLETED'`.
5. При совпадении обоих ответов выполнение завершается с
   `NATURAL_COMPLETION_CONFIRMED`, без запроса STOP.
6. При отказе старта, ошибке, несовпадении события, недоигранном
   количестве повторов или тайм-ауте остаётся компенсационный STOP
   обоим каналам с ограничением ожидания.

При штатном завершении ожидается автоматический возврат к программе.
Проверка физической слышимости остаётся отдельной от статуса
локального аудиопроцесса.

## Безопасность и границы

- Изолированный учебный режим сохраняет запреты на публичный эфир
  и усилитель.
- Android-уведомления не получают права автоматически запускать
  этот исполнитель.
- Источник события и реальная передача на два выхода ещё не
  считаются подтверждёнными.
- Возможность аварийно завершить неисправную сессию сохраняется,
  но штатная сессия не требует STOP.
