# МЧС / Radio Worker: одна сессия ALARM на одно уведомление

Этот этап устраняет обнаруженную несовместимость прежнего
`mchsVerifiedWorkerTransport` с повторным PCM-воспроизведением Worker
из PR #955.

## Контракт аудио

1. Получить подтверждение, что Worker свободен.
2. Отправить ровно один `START(assetId,repeats)` для всего ALARM-файла.
3. Убедиться, что Worker активен и его `revision`, `assetId`, `repeats`
   соответствуют запущенной сессии.
4. Отслеживать `completedRepeats` без повторного START между повторами.
5. Признать естественное завершение только при `active=false`,
   `revision=startRevision+1`,
   `lastStopReason=FILE_COMPLETED` и ровно `repeats`
   завершённых воспроизведениях.
6. Освободить блокировку адаптера; следующему отдельному событию
   разрешить новую сессию.
7. При ошибках/чужой ревизии сохранять блокировку до подтверждённого
   останова Worker. Если стартовый ответ некорректен, сделать STOP
   с проверкой результата.

Опасность: 1–5 полных повторов. Отбой: один полный проход.
Радиопрограмма не появляется между повторами. Обычный
STOP **не требуется** после успешного `FILE_COMPLETED`.

## Границы

Адаптер использует нынешний `mchs-training-stream`, способный
подменять публичный PCM. Он **не подключается** к живому Android-интенту
и не даёт новой власти на публичную тревогу. Вызов разрешён
только для отдельно изолированного аудиовыхода с действующими
существующими ограничениями. Реальная автоматическая трансляция
останется отключённой до подтверждённого происхождения уведомлений,
готовности Worker и Agent, независимого завершения и согласованного
испытания в аудиотракте.
