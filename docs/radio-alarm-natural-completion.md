# Политех-FM — завершение ALARM по концу файла

## Изменение

Ветка добавляет детерминированный PCM-цикл, не зависящий от ручного STOP
при штатном завершении:

- Worker получает файл категории `ALARM` и параметр `repeats` от 1 до 5;
- декодирует файл один раз и воспроизводит **все сэмплы** указанное число раз,
  не вставляя музыкальный фрагмент между повторами;
- на последнем сэмпле возвращает исходную станцию, освобождая источник;
- состояние сообщает число завершённых повторов, прогресс и
  `lastStopReason=FILE_COMPLETED`;
- при недочитанном файле выдаёт ошибку, не подтверждает окончание;
- серверная образовательная последовательность запускает опасность одним
  вызовом START с `repeats=N`, затем один раз отбой с `repeats=1`;
- Windows `AlarmPlaybackSession` различает натуральное `COMPLETED` и
  `STOPPED` после сбоя, выводит `failureReason`.

## Границы

Изменение **не активирует автоматическое вещание** при Android push.
Код приёма уведомлений и обязательная проверка подлинности отправителя
остаются в существующем контуре наблюдения. `MCHS_EXECUTION_POLICY` и
`MCHS_DISPATCH_PROTOCOL` остаются заблокированными по умолчанию.
Изолированный маршрут и выключенный по умолчанию
`RADIO_MCHS_TRAINING_STREAM_ENABLED` остаются прежними.

Для дальнейшей производственной интеграции требуются подтверждённое
происхождение уведомлений приложения, независимая привязка Agent к физическому
выходу и проверка end-to-end в согласованном учебном эфире. Команды
аварийного завершения не входят в нормальный путь, но должны оставаться
доступными при неисправности.

## Автоматическая проверка

```bash
cd server
node --test tests/radioMchsTrainingOverlay.test.js tests/mchsTrainingSequence.test.js
cd ../radio-agent/windows
python -m unittest test_mchs_alarm_playback
```

Ожидаемые критические инварианты:
1. Никакого преждевременного возврата между полными повторами.
2. Ни один недочитанный файл не считается успешно завершённым.
3. Отбой воспроизводится один раз и только после окончания опасности.
4. Повторно пришедший сетевой пакет не перезапускает уже завершённый
   `AlarmPlaybackSession` для того же `event_id`.
5. Прежний радиотракт восстанавливается после `FILE_COMPLETED`.
