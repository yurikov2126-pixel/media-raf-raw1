# Радио 2.0 — этап 3 (редактор и недельная сетка)

## Реализовано
- Не меняя внешний вид главной страницы, добавлены операции с аудиозаписями: переименование и удаление только если запись не используется.
- Перестановка файлов в плейлисте перетаскиванием (кнопки вверх/вниз сохранены для мобильных устройств и доступности).
- Недельное представление расписания на базе существующих событий.
- Создание повторяющихся слотов на срок от 1 до 12 недель с атомарной проверкой пересечений; при конфликте ни один слот не записывается.

## Важное ограничение
Повторение рассчитывается по дням **UTC**, а одиночное время пользователь задаёт локально. Это **промежуточный редактор расписания**, не средство запуска оборудования. Перед интеграцией с Windows Agent необходимо добавить фиксированный часовой пояс радиостанции (IANA), включая корректную обработку переходов времени. Не использовать его как гарантированное расписание трансляции.

## Ubuntu 24.04 и aaPanel
Новых серверных пакетов для этапа 3 не требуется. Используется существующий Node.js/Prisma/PostgreSQL. `ffprobe` уже установлен пользователем: `/usr/bin/ffprobe`, версия 6.1.1. Системные службы и nginx/aaPanel этим PR не изменяются.

## Проверки перед merge
1. CI: тесты и сборка frontend/backend; проверить существующие Prisma-модели.
2. Под ADMIN переименовать свободный файл, затем удалить его.
3. Попробовать удалить файл, используемый в плейлисте: ожидается HTTP 409, файл остаётся.
4. Перетащить запись, сохранить плейлист, перезагрузить страницу: порядок сохраняется.
5. Добавить события в неделю и убедиться, что они отображаются по дням.
6. Создать повторяющееся расписание и проверить пересечения: никакой частичной записи.
7. Проверить, что роль STUDENT не может вызвать /api/radio/*.
8. Убедиться, что на Windows Agent и ESP32 никакие команды не отправляются.
