# PR #1015 — отдельная production-привязка радиокомпьютера для диагностики МЧС

## Проблема

Административный `GET /api/safety/missile-main-station-readiness` использовал `MCHS_AGENT_LAB_DEVICE_ID` для определения реального Windows Radio Agent. Это пережиток испытаний: в панели основного тракта могла отображаться лабораторная привязка вместо рабочей. При просмотре журнала использовался первый ESP32 с совпадающим `reporterId`, без проверки свежести и единственности.

## Реализация

Добавлена независимая production-переменная окружения API:

`MCHS_MAIN_STATION_AGENT_DEVICE_ID=<ID зарегистрированного рабочего Windows Radio Agent>`

Значение должно соответствовать полю `id` активного `radioDevice` (не токену доступа `rr_` и не IP). Администратор настраивает эту переменную в окружении `mediaraf-api.service` и перезапускает службу в согласованное окно обслуживания. Никаких секретов для настройки новой переменной не требуется.

Приоритет привязки:
1. `MCHS_MAIN_STATION_AGENT_DEVICE_ID` — явная **основная** привязка;
2. `MCHS_AGENT_LAB_DEVICE_ID` — **устаревшая** привязка для наблюдения при миграции, показываемая как `LEGACY_LAB_FALLBACK`;
3. при отсутствии обоих значений — `UNCONFIGURED`, никакие другие устройства автоматически не выбираются.

**Новая переменная затрагивает только административный read-only маршрут основной станции.** Остальные учебные контроллеры/ограничения не меняются и не получают разрешения на запуск.

Для журнала событий ESP32 выбирается **ровно один** контроллер, привязанный к этому Agent с наблюдением возрастом не более 12 секунд. Если два контроллера свежие или все данные устарели, ответ содержит явную причину: `AMBIGUOUS_FRESH_ESP32`, `NO_FRESH_ESP32` или `NO_BOUND_ESP32`. События другого устройства подставляться не будут.

Административный интерфейс показывает режим привязки и причину недоступности журнала. Все флаги физической готовности остаются `false`, так как ни heartbeat, ни телеметрия GPIO13 не подтверждают фактическую подачу 220 В или наличие звука в громкоговорителях.

## Проверка после объединения

- Задать ID именно действующего Windows Agent в production-переменной.
- Убедиться, что Agent и ESP32 работают с версиями из PR #1012–#1014 и постоянно отправляют отчёты.
- Открыть «Экстренное оповещение → Тракт оповещения» и проверить, что нет предупреждения о лабораторной привязке и отображаются два независимых признака доставки телеметрии.
- При отключённой силовой цепи проверить, что краткий цикл GPIO13 (без подключения AA-300) отражается в событиях firmware; ошибки по Wi-Fi/lease сопоставляются с решениями Agent.

Этот PR **не перепрошивает ESP32, не обновляет Windows EXE, не включает усилитель и не активирует автоматическую тревогу**. Никакой административный экран не может доказать наличие PA-звука без независимого физического контроля.
