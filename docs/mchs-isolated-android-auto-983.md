# МЧС — автоматический Android → WAV в изолированных наушниках (PR #983)

## Назначение

В существующем Windows Agent `--isolated-event-audio` автоматически принимаются
НОВЫЕ сообщения «Ракетная опасность» / «Отбой ракетной опасности», полученные
через подписанный Android ingest, **только в локальных наушниках**. Это не
публичный ALARM, не автоматическая разблокировка Worker, усилителя AA-300 или PA.

## Что необходимо

1. Проводка всех PA/AA-300 физически отсоединена; оператор запустил Agent
   с `--enable-headphones-test --isolated-event-audio`, ввёл `ISOLATED`.
2. В существующей настройке сервера `MCHS_AGENT_LAB_DEVICE_ID` указан
   фактический Device ID Windows Agent. `MCHS_INGEST_ENABLED` и
   `MCHS_INGEST_HMAC_KEY` настроены для авторизованного Android-моста.
3. `MCHS_MISSILE_TRUSTED_CHANNEL_IDS` содержит разрешённые channelId
   Android-уведомлений, регион должен быть «Тульская область».
4. Только для временного испытания наушников администратор сервера включает
   `MCHS_ISOLATED_ANDROID_AUTO_TRIAL_ENABLED=true`. По умолчанию false.
   `MCHS_ISOLATED_DANGER_REPEATS` — 1–5 (по умолчанию 1); отбой всегда 1.
5. Agent регулярно передаёт действительную телеметрию
   `MCHS_ISOLATED_READY_REPORTED`, с подтверждёнными локальными WAV и
   центральными аудиопакетами.

## Исполнение

- При опросе существующего `/api/radio-agent/agent/mchs-execution-command`
  сервер (в транзакции PostgreSQL) выбирает свежее Android-событие разрешённого
  канала и формирует **отдельную, явно помеченную `trialOnly` команду**.
- Защита от повторов хранится в `mchs_agent_isolated_android_auto_v1_<DEVICE_ID>`,
  командный `sequence` монотонный, событие старше 120 секунд не стартует.
- Отбой не запускается до ранее зарегистрированной опасности и терминального
  отчёта об естественном завершении WAV с возвратом центральных пакетов.
- Перед следующим событием Agent должен вернуть подтверждение `COMPLETE`.
  При `FAILED` сценарий не продолжается автоматически.
- Временная остановка центрального VLC во время локального WAV не считается
  командой HALT. Явно зарегистрированный глобальный haltEpoch и STOP имеют
  приоритет над тестовой автоматикой.
- Исходные уведомления сохраняют `verified:false`. Признак
  `trialSourceAccepted` допускается **только для локального изолированного
  испытания**, а не как доказательство официального происхождения сообщения.
- Результаты возвращаются в существующий журнал Windows Agent в
  «Экстренное оповещение → Уведомления».

## Важные границы

**Производственное оповещение учащихся этим PR не включается**.
В частности, PR не меняет Worker, MP3-поток, ESP32, программу усилителя
или подтверждение фактической слышимости громкоговорителей. Общий протокол
реального аварийного исполнения остаётся заблокированным. Если ранее был
установлен `haltEpoch`, отдельная изолированная автоматическая ветка также
не выдаст START: этот контроль нельзя скрытно обходить.

## Проверка

```bash
cd server
node --test tests/mchsIsolatedAndroidAutoFeed.test.js
cd ../radio-agent/windows
python -m unittest -v test_mchs_isolated_android_auto_command
```

Тестировать надо с реальным уведомлением разрешённого канала, физически
отключённым PA и запущенным наушниковым Agent. Не инициировать настоящую
тревогу ради проверки; использовать контролируемый тестовый входной сигнал,
явно помеченный испытанием.
