# Radio 2.0 — Windows Radio Agent: этап синхронизации (БЕЗ ВОСПРОИЗВЕДЕНИЯ)

## Возможности
- Раздел «Радио → Оборудование»: создание/отзыв доступа радиокомпьютеру. Токен показывается только при регистрации, в PostgreSQL хранится только SHA-256.
- Отдельные защищённые маршруты `/api/radio-agent/agent/status`, `/agent/snapshot`, `/agent/assets/:id`. Администраторские маршруты `/devices`.
- Снапшот содержит только утверждённые передачи на ближайшие 14 суток (с запасом 1 час в прошлое). Неутверждённые передачи не публикуются. Аудио выдаётся только при наличии связи с актуальными утверждёнными слотами.
- `radio-agent/windows/sync_agent.py` — Windows-клиент только скачивает, проверяет SHA-256 и записывает локальный snapshot. Ничего **не воспроизводит**. Удалённого управления питанием нет.

## Ubuntu 24.04 + aaPanel: инструкция

**Нужно применить новую Prisma-миграцию** `20261017100000_radio_devices`. Никаких новых apt-пакетов для сервера не требуется. Используйте ваш стандартный production deploy с резервной копией БД → git pull → prisma generate/migrate deploy → build → restart. Не запускайте параллельные ручные миграции. Убедитесь, что nginx/aaPanel обслуживает `/api/radio-agent/*` тем же защищённым Node API, что и `/api/radio/*` (существующий общий proxy /api). Используйте только HTTPS.
После деплоя войдите под ADMIN → Радио → Оборудование → «Зарегистрировать радиокомпьютер». Сохраните токен в безопасном месте. Не включайте токен в GitHub issue, PR, скриншоты или логи.

## Windows 10 (выделенный ноутбук)

Дополнительные Python-пакеты (**pip**) не требуются. Потребуется Python 3.11+ с официального python.org, если Python отсутствует. При установке отметить `Add python.exe to PATH`. Учтите, что обычная поддержка Windows 10 завершилась 14 октября 2025 года: используйте поддерживаемую ОС или ESU, особенно если устройство постоянно подключено к интернету.

Откройте PowerShell на ноутбуке, сохраните `radio-agent/windows/sync_agent.py` из репозитория в `C:\RadioAgent\sync_agent.py`. Переменную `RADIO_AGENT_TOKEN` следует задавать **локально, в текущей сессии**, а не помещать в общий командный файл:

```powershell
python --version
$env:RADIO_AGENT_TOKEN = Read-Host "Вставьте одноразово выданный токен устройства"
python C:\RadioAgent\sync_agent.py --server https://mediarafraw.ru --data-dir C:\RadioAgent\data --once
Remove-Item Env:\RADIO_AGENT_TOKEN
```

Токен — секрет: не копируйте PowerShell с токеном в скриншоты, историю команд или облачные синхронизируемые папки. Для непрерывной работы без участия пользователя в будущем потребуется отдельная защищённая настройка учётных данных и служба/планировщик Windows.

После удачной синхронизации в `C:\RadioAgent\data\cache` появятся бинарные копии записей, `snapshot.json` — расписание. Из аудио никто ничего не проигрывает. Контрольная сумма защищает от повреждения при скачивании, но для защиты от компрометации сервера и смены расписания отдельно потребуется подпись/проверка целостности подписанного манифеста перед включением автоматического эфира.

## Проверки перед merge
- Клиент не содержит кода воспроизведения, управления ESP32/AA-300 и аварийных команд.
- ADMIN может зарегистрировать устройство и отозвать токен; STUDENT получает 403 на /devices.
- Неверный/отозванный токен возвращает 401 на /agent/status и /agent/snapshot.
- Снапшот включает только APPROVED; файлы проверяются по SHA-256.
- Проверить на Windows с `--once` и сверить список загрузок с опубликованной сеткой.
- Выполнить CI, Prisma migrate deploy и клиентскую сборку на тестовом окружении перед включением production.
