# Радио 2.0 — пакет улучшений аудиотеки и плейлистов

## Изменения
- Массовое добавление файлов в очередь, перетаскивание в область загрузки, последовательная отправка на существующий защищённый API, общий прогресс по количеству файлов и список ошибок.
- Один общий аудиоплеер вместо создания нового элемента Audio для каждого прослушивания.
- Исходные имена файлов на кириллице передаются через UTF-8 поле filename (Multer отдельно проверяет расширение и аудиозаголовок). Данные пользовательского имени никогда не используются как путь хранения.
- Пошаговое создание плейлиста: название и описание -> массовый выбор файлов из аудиотеки -> перестановка -> сохранение.
- Администратор может редактировать утверждённые плейлисты. Для будущих слотов в одной транзакции пересчитывается конец передачи, при конфликте правка отклоняется.
- Исходный экран «Радио» и доступ только ADMIN сохранены.

## Установка на Ubuntu 24.04 и aaPanel
Новые системные пакеты, npm-зависимости и миграции Prisma для этого PR **не нужны**.
Используются действующие пакеты Node.js/Prisma и ffprobe по /usr/bin/ffprobe.
Деплой выполняется штатным механизмом проекта после зелёного CI; менять nginx/aaPanel и настройки service unit не нужно.
Текущий серверный предел сохраняется: **30 МиБ на один файл**, а не 30 МиБ на всю очередь. Каждый файл загружается отдельным запросом.

## Проверить перед merge
1. Upload 3 аудиофайлов одновременно через file picker и drag-and-drop; проверить прогресс и ситуацию когда один файл повреждён.
2. Проверить русские имена вроде «Новости колледжа №2.mp3»; после загрузки и перезагрузки интерфейса название должно сохраниться.
3. Общий плеер переключает записи; одновременно два потока не играют.
4. Создать плейлист в 3 шага: выбрать несколько аудио, переставить, сохранить, снова открыть на редактирование.
5. Изменить утверждённый плейлист без эфиров; статус APPROVED сохранён.
6. Изменить утверждённый плейлист с будущим эфиром: проверить перерасчёт endAt; при конфликте должен вернуться 409, без частичных правок.
7. API по-прежнему отвергает STUDENT; нет команд реальному усилителю, Windows Agent или ESP32.

## Ограничения
- Прогресс массовой загрузки учитывает **файлы**, не байты, чтобы не вводить в заблуждение.
- Большие очереди передаются последовательно во избежание высокой нагрузки на Ubuntu.
- В будущей версии для реального локального радиоклиента понадобится неизменяемое версионирование опубликованных программ/снимков расписания: непосредственное изменение текущего плейлиста будет недостаточно для безопасной синхронизации устройств.
