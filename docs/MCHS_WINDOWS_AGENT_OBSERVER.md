# Интеграционный наблюдатель МЧС в штатном Windows Radio Agent

Этап OBSERVE_ONLY: обычное радио **не останавливается** и **не изменяется**.
Agent во время своего основного цикла с интервалом примерно 5 секунд
опрашивает read-only `/api/radio-agent/agent/mchs-integration-observe`.

Доступ возможен только если в окружении API установлены
`MCHS_AGENT_LAB_STREAM_ENABLED=true` и
`MCHS_AGENT_LAB_DEVICE_ID=<ID именно этого агента>`.
По умолчанию доступ закрыт (HTTP 403). Отдельный тестовый токен не требуется,
но следует привязывать только разрешённое устройство, не выдавать доступ
всем агентам. Если API недоступен, звуковой тракт продолжает обычную работу.

В журнале Agent при изменении ревизии появляется `MCHS_AGENT_OBSERVER`
с `workerPhase`, `revision`, `stationPlaybackChanged:false` и
`paOutputChanged:false`. Эти значения — **обозначение режима**, а не
измерение физического выхода. При ошибках: `MCHS_AGENT_OBSERVER_UNAVAILABLE`.

В админке МЧС оставлены актуальные средства диагностики Worker,
PCM-сессия с реальными учебными файлами и состояние готовности.
Убраны дублирующие ручные панели синтетических WAV, старого микшера
и браузерного локального файла; исходные тестовые библиотеки и
автоматические unit-тесты в этом PR не удалены, чтобы не нарушить
диагностические API и регрессионные проверки.

Для проверки: (1) подтвердить работающий основной радиоэфир;
(2) включить доступ только для выбранного Agent;
(3) запустить учебную PCM-сессию в панели МЧС (только в браузере);
(4) увидеть обновление ревизий в журнале Windows Agent;
(5) подтвердить, что обычный звук не прерывался;
(6) выключить флаг в API. Этот этап не разрешает подачу
учебных объявлений на AA-300, ESP32 и громкоговорители.

Следующий этап — отдельно проектировать проверяемый аудио-маршрут
с реальным физическим приоритетом и согласованием ответственного
по безопасности. Радио не заменяет штатную систему эвакуации.
