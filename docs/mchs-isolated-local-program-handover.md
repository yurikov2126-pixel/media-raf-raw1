# МЧС #966 — изолированный алгоритм перехода программы в учебный звук

После #965 локальное воспроизведение WAV может естественно завершать все
повторы. Здесь введён отдельный контроллер последовательности:

1. Подтвердить физическую изоляцию выходов от AA-300/PA.
2. Приостановить локальную программу с подтверждением завершения процесса.
3. Воспроизвести учебный файл с точным количеством повторов.
4. Подтвердить естественное окончание всех повторов.
5. Восстановить локальную программу и подтвердить её работоспособность.

Функция: `radio-agent/windows/mchs_local_handover.py:run_isolated_handover`.

В случае ошибки учебного воспроизведения всё равно выполняется попытка
возврата локальной программы. При неуспешном подтверждении восстановления
контроллер не объявляет успех. Без подтверждения остановки программы
учебное аудио вообще не запускается.

**Текущая граница:** это тестируемая логика с передаваемыми адаптерами,
пока не подключённая к действующему `central_playout.py`. Новые тесты
проверяют порядок вызовов и состояния, но не реальные аудиопроцессы.
Никаких автоматических START по Android, Worker PCM overlay, публичной
трансляции или ESP32 этот PR не добавляет.

Тест:

```powershell
cd radio-agent/windows
python -m unittest -v test_mchs_local_handover test_mchs_headphones_trial
```

Следующим этапом может стать интеграция контроллера с изолированным
Windows audio pilot с измерением возвращения центральных PCM пакетов.
