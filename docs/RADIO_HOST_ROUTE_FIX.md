# Исправление входа в Радио для радиоведущего

У администратора главная страница Радио: `/app/radio`.
У студента, которому в Команде редакции назначена системная должность `RADIO_HOST`: `/app/radio/playlists/my`.

При открытии общего адреса `/app/radio` авторизованный студент-радиоведущий теперь автоматически попадает в свой редактор, а не перенаправляется на главную платформы. Пользователи без соответствующей должности по-прежнему не допускаются; проверка `/api/radio/access` и защита `/api/radio/student/*` остались прежними.

## Проверка
1. В админке назначить тестовому студенту должность Радиоведущий (код RADIO_HOST).
2. Перезагрузить страницу в студенческой сессии и открыть `/app/radio`: ожидается переход на `/app/radio/playlists/my`.
3. Проверить `/app/radio/playlists/my` напрямую — должны открыться собственные плейлисты.
4. Обычный студент по обоим адресам должен получить отказ/перенаправление; `/api/radio/student/playlists` у него должен вернуть 403.
5. Администратор `/app/radio` должен по-прежнему открывать свой пульт.
6. Если радиоведущий всё ещё не входит, проверить Network → `GET /api/radio/access`: `allowed: false` означает проблему назначения должности/серверной проверки, а `allowed: true` — проблему интерфейса или настроек меню.
