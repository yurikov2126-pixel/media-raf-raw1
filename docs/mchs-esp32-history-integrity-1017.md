# PR #1017 — корректный переход на новую прошивку и причины GPIO13 OFF

## Исправляемая ошибка
Старый ESP32 мог уже сообщать `bootNonce` и счётчики переходов, но не иметь поля `relayTransitionSequence`. При первом сообщении от обновлённой прошивки исходное сравнение принимало отсутствующий курсор за ноль и заносило все последние переходы кольцевой истории в журнал как произошедшие между двумя опросами. Это могло создавать ложные «новые» отключения. Теперь первая история после обновления считается **базовым снимком**. Только следующие переходы той же загрузочной эпохи учитываются как новые.

Также валидатор прошивки теперь принимает `UNSPECIFIED_OFF` — реальный код по умолчанию `powerOff()`, который ранее мог отклонить весь корректный пакет из-за одного перехода.

## Сводка в административном интерфейсе
В «Экстренное оповещение → Тракт оповещения → История управления усилителем» показываются:
- число *наблюдавшихся командных* переходов GPIO13 в OFF за последние 10 минут из доступного ограниченного журнала;
- причина и номер последнего такого перехода;
- группировка по кодам причин (`HEARTBEAT_TIMEOUT`, `POWER_LEASE_EXPIRED`, `SIGNED_PERMIT_FALSE` и т.д.);
- число зарегистрированных пропусков телеметрии, перезагрузок и переполнений буфера.

Это read-only агрегирование только событий текущего выбранного ESP32. Изменения не управляют реле и не модифицируют автоматическую МЧС-цепочку.

**Важные границы:** сводка основана на последних 70 событиях из 10-минутного окна, а не на гарантированно полной записи всех переходов; `OFF` — это команда выводу GPIO13, а не независимое измерение питания усилителя AA-300 или громкости его динамиков. Отсутствие OFF в сводке не доказывает стабильность физического питания. При неверно выставленных часах Windows или потере Wi-Fi часть событий может отсутствовать.

## После объединения
Выберите реальный Windows Agent в production-настройке, которая уже доступна после PR #1016. Убедитесь, что ESP32 работает на прошивке с `relayTransitionHistory`, а Agent на версии с передачей диагностических данных. Проверяйте временную шкалу и причины при безопасном контроле без подключённой силовой нагрузки; результаты аппаратной проверки отдельно необходимы для заключения об исправности PA.

Серверные тесты проверяют переход со старой прошивки, отсутствие повторного учёта исторических OFF, допустимый `UNSPECIFIED_OFF`, раздельный учёт firmware и Agent и привязку агрегатов к конкретной ESP32.
