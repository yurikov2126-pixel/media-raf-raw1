# Radio Agent macOS — более быстрый резерв и автоматическая загрузка сетки

## Изменения
- Контроль соединения и краткая проверка MP3 вынесены из критического цикла воспроизведения в отдельный поток: при потере сети локальная музыка больше не должна ожидать HTTP-тайм-аут проверки доступности.
- Тайм-аут получения потока уменьшен до 2,5 с, контроль отсутствия данных — до 3 с. VLC сетевой буфер уменьшен с 800 до 250 мс для сокращения задержки старта.
- При обратном переходе на сервер резервная запись останавливается только после первых пришедших байтов центрального потока. Это **не гарантирует переход без тишины**: первые байты не равны звуку на аудиовыходе.
- После нажатия «Проверить связь» (теперь это подключение + загрузка) агент автоматически загружает материалы и проверяет `snapshot.revision` каждые 15 с, повторно синхронизируя файлы только при изменении сетки. Центральный проигрыватель также обновляет кэш в фоне.
- Интерфейс: статус источника звука и состояния кэша вынесены наверх; устаревшие тесты локального воспроизведения/микрофона/WebRTC доступны под переключателем «Показать дополнительные тесты», но не удалены.

## Важно
- Токен по-прежнему живёт только в памяти. Без предоставленного токена агент при старте приложения не может автоматически подключиться — нажмите «Проверить связь» после ввода токена. Автовозобновление после старта без повторного ввода потребует отдельной безопасной интеграции с macOS Keychain.
- На первичном подключении к уже идущему **живому** MP3 нельзя воспроизвести звуковую секунду, прошедшую до подключения. Уменьшение буферизации должно снизить задержку, но для гарантированного старта по границе передачи необходима серверная предварительная буферизация/маркер синхронизации.
- Для практически бесшовного failover нужны два декодера с общим аудиовыходом и подогретым локальным резервом; текущая реализация с двумя VLC-процессами может давать кратковременные паузы.
- UI/переключение требуют Mac QA; наушники, никакого AMP/реле/ESP32.

## Проверка
1. `cd radio-agent/macos && python3 -m py_compile gui.py central_playout.py sync_agent.py && python3 -m unittest -v test_central_playout.py`
2. Введите токен, нажмите «Проверить связь»; убедитесь, что кэш заполнился. Измените будущую сетку на сайте и убедитесь в загрузке новой ревизии спустя ~15–30 с.
3. Включите центральный эфир, оцените потерю начала записи и качество MP3.
4. Отключите Wi-Fi, засеките паузу до локальной записи, восстановите Wi-Fi, проверьте отсутствие двух источников одновременно.
5. Повторите 3–5 раз, включая смену композиции. При ошибке приложите журнал GUI и `central-vlc.log`.
