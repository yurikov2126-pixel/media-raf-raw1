# Radio 2.0 — устойчивость переходов Crossfade

## Изменения
- В серверном Worker восстановление в середине перехода использует `atrim/asetpts` внутри FFmpeg filtergraph, чтобы выбранная часть двухдекерного микса не зависела от выходного `-ss`.
- Перед созданием двухвходного FFmpeg проверяется доступность следующего аудиофайла; если его нет, переход не запускает гарантированно неработающий второй вход, а записывает диагностическую ошибку и продолжает однодекерный фрагмент.
- Механика Auto-DJ/Cue, API и существующие значения Crossfade не меняются. Ни одна настройка автоматически не активируется.

## Ограничения
Это **укрепление текущего пилота**, а не уже достигнутое гарантированно бесшовное вещание. Между декодируемыми сегментами по-прежнему запускается новый FFmpeg процесс, что может вызвать слышимый разрыв. Следующий полноценный шаг — постоянные декодеры, предварительный PCM буфер и единый тактовый вывод, затем нагрузочный тест. Не обещать нулевые паузы до воспроизводимых измерений.

## Проверки
- CI Node / frontend build; отдельно проверить `node --check server/workers/radioPlayout.js`.
- Только наушники: Auto-DJ с двумя треками, Cue In/Out, 0/1/3/5 с Crossfade.
- Перезапуск Worker посреди перехода, отсутствующая следующая запись, точный старт передачи и отключение Auto-DJ.
- Физический PA, усилитель и ESP32 не подключать; сервис Worker перезапускать отдельно после merge.
