# Радио 2.0 — Эфирная студия / WebRTC Pilot

## Возможности
Тест прямого звука с браузера смартфона (микрофон) на другой авторизованный браузер Mac/ПК. В Радио → «Эфирная студия»:
- на телефоне: «Начать эфир с микрофона», разрешить доступ, следить за статусом, «Выключить микрофон» / «Завершить тест»;
- на Mac: открыть ту же страницу под ADMIN, нажать «Принимать эфир на этом устройстве», затем при необходимости «Включить звук» (ограничения автозапуска браузера).

На сервере добавлен защищённый ADMIN-only Socket.IO signaling, только один ведущий и один приёмник. RTP-аудио идёт напрямую по WebRTC (P2P), не через Socket.IO и не записывается в БД.

## Порядок теста
1. Обновить сайт через стандартный deploy (Node API + клиент). Никаких миграций не требуется.
2. Mac: подключить наушники, не подключать AA-300 или общие динамики.
3. Авторизоваться под ADMIN на Mac и смартфоне, открыть «Радио → Эфирная студия».
4. На телефоне нажать «Начать эфир с микрофона», разрешить микрофон.
5. На Mac нажать «Принимать эфир на этом устройстве» и «Включить звук», если Safari/Chrome требует пользовательского действия.
6. Проверить звук, заглушение микрофона и завершение. Закрытие вкладки тоже завершает тестовую сессию.
7. При ошибке WebRTC проверить консоль браузера и наличие HTTPS. В разных сетях может понадобиться TURN, он пока **не настроен**.

## Безопасность и ограничения
- Этап ограничен пользователями с ролью ADMIN; роль радиожурналиста, очереди эфиров и модерация пока не включены.
- Приём только через браузер Mac, **не в настольном Python Radio Agent**. Поэтому никакого автоматического переключения между плейлистами и прямым эфиром нет.
- WebRTC использует общедоступный STUN Google; при строгом NAT без TURN соединение может не установиться. Не утверждайте, что функция работает через любые мобильные сети до добавления собственного TURN.
- Запрещено использовать как систему обязательного или экстренного оповещения.
- Никаких команд ESP32, реле или усилителю.

## Ubuntu 24.04 + aaPanel
Новых apt-пакетов, npm-зависимостей, Prisma-миграций нет. Используются текущие Socket.IO 4.8, браузерный WebRTC, HTTPS и существующий Nginx reverse proxy. Для socket.io должен сохраняться WebSocket upgrade, как для чатов сайта.
