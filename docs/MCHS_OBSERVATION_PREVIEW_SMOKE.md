# MCHS Bridge V2 → Media-РАФ-RAW: наблюдение, этап 1

Это **подготовка и ручная smoke-проверка preview API**. Она не подключает Android V2, не получает реальные уведомления и не запускает радио.

## Уже существует в проекте

- Preview API `POST /api/safety-ingest/event` с feature flag `MCHS_INGEST_ENABLED=true` и отдельным ключом `MCHS_INGEST_HMAC_KEY` (не менее 32 символов).
- Сервер подписывает не так, как Android localhost-лаборатория: HMAC-SHA256 от **timestamp + "." + точных байтов JSON**; заголовки `X-MCHS-Timestamp`, `X-MCHS-Signature: sha256=<hex>`.
- Ответ ACK требует `accepted:true`, `eventId` равен исходному, `testOnly:true`, `verified:false`.
- Таблица событий идемпотентна по source+eventId, доступ к `GET /api/safety/dashboard` / `/events` через `safety.view`.
- Включение радио и громкоговорителей в этом контуре запрещено.

## Smoke-прогон на preview (только искусственный payload)

1. На preview убедиться, что Prisma миграции применены. Включить ingest **только на preview** и задать сильный ключ в приватном конфиге окружения сервиса. На production ingest остаётся выключенным.
2. Ограничить доступ к приёмнику по VPN/IP и rate limit на nginx. Убедиться, что сертификат TLS валиден.
3. На авторизованной машине установить **тот же preview-ключ** в окружение как `MCHS_PREVIEW_INGEST_HMAC_KEY` (не писать в команды истории, логи или git).
4. Запустить:
   ```bash
   python3 tools/mchs-sender/preview_smoke.py --url https://preview.mediarafraw.ru/api/safety-ingest/event --repeat
   ```
5. Ожидается два ACK с **одинаковым идентификатором записи**, то есть сервер не создаёт дубль.
6. В preview `/app/safety` убедиться, что появилась ровно одна запись «ТЕСТ: диагностика приёмника» со статусом непроверенного события.
7. После теста выключить preview ingest либо оставить включённым только по отдельному утверждённому плану эксплуатации стенда. Production не менять.

Скрипт не загружает уведомления, использует только случайный UUID с префиксом `observation-smoke-`, отказывается работать с production hostname. Запрос выполняется только один-два раза по явному запуску.

## Требования к следующему Android V2 патчу

1. В отдельной диагностической конфигурации preview endpoint и **отдельный ключ, отличный от ключа localhost-лаборатории**; не хранить ключ в исходниках или APK.
2. Сохранить текущие `https_hmac_diagnostic` записи, ACK и lease; не переиспользовать локальный `/diagnostic/ack` контракт для preview.
3. Отправлять только отдельное **синтетическое** событие; исключить чтение таблицы `events` и реальных NotificationListener payload.
4. Preview ACK сохранять только после строгой проверки `accepted`, `eventId`, `testOnly`, `verified=false`. Хранить локальную durable очередь и идемпотентный идентификатор.
5. Протестировать недоступность preview, некорректный ответ, двойной POST, время/подпись и конкурентность. Реальные оповещения не подключать до проверки фактического захвата, подлинности и правил ручного подтверждения.

## Ограничения

Наблюдение за push-приложением не является официальным или гарантированным каналом экстренного оповещения. Факт получения HMAC-запроса не подтверждает происхождение уведомления. Не используйте данный тест для прерывания эфира или управления звуковым оборудованием.
