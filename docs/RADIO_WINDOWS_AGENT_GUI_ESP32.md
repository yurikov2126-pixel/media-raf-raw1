# Windows Radio Agent 0.3 — ESP32, фирменное окно и автозапуск

В Windows Agent появились настройки ESP32 для локальной сети Studio, диагностика сопряжения, значок программы и опциональный автозапуск окна при входе в Windows.

## Как установить

1. Скачайте **новый** собранный EXE из артефакта GitHub Actions «Windows Radio Agent EXE» после успешной сборки PR. Предыдущие версии не содержат новых настроек ESP32.
2. Поместите EXE в постоянный каталог, например `C:\RadioAgent\MediaRafRaw-RadioAgent.exe`. Для автозапуска важно не перемещать EXE после включения опции.
3. Откройте GUI: раздел **ESP32 · локальная инфраструктура** → IP `10.0.1.58`; укажите **новый** локальный секрет, который совпадает с прошивкой.
4. Нажмите «Проверить связь». Даже без запуска радиоэфира приложение будет посылать `STOPPED` heartbeat каждые 3 секунды. `heartbeatCount` должен расти.
5. Включите «Открывать агент при входе в Windows», если нужен автозапуск **самого окна**. Эфир не запускается автоматически: всё ещё требуется явное разрешение сервера и подтверждение теста в наушниках.
6. Настройки IP, сервера и VLC сохраняются в `%LOCALAPPDATA%\MediaRafRaw\RadioAgent\settings.json`. Токен радиоагента и секрет ESP32 **не сохраняются** и вводятся заново при запуске. Это означает, что после перезагрузки Windows без ручного ввода секрета heartbeat не начнётся.

## Проверки и безопасность

- PowerShell: `Test-NetConnection 10.0.1.58 -Port 80`, затем браузер `http://10.0.1.58/health`.
- `heartbeatCount` увеличивается от сообщений GUI, `heartbeatFresh` становится `true`.
- `agentMode=STOPPED` до старта воспроизведения — ожидаемое состояние, не ошибка.
- Если появляется `HTTPError: неверный секрет (403)`, прошейте ESP32 с новым секретом и укажите его в GUI.
- Прежний секрет сопряжения был опубликован в переписке, поэтому его необходимо заменить перед использованием.
- **ESP32 SAFE_PILOT не включает GPIO13 и не управляет 220 В.** Усилитель не подключать к сетевой нагрузке при тестах.
- Автозапуск — ключ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; включается только пользователем. Программа не создаёт службу Windows и не имеет фоновой работы без входа пользователя.

## Как работает обновление (важно для 0.2.0)

Сборка `Artifacts` в GitHub Actions **не является GitHub Release**. Встроенный updater версии 0.2.0 читает только `https://api.github.com/repos/yurikov2126-pixel/media-raf-raw1/releases?per_page=20`, пропускает черновики/предрелизы и принимает только тег `radio-agent-vX.Y.Z`, файл `MediaRafRaw-RadioAgent.exe` и валидный SHA-256 в метаданных GitHub. На момент исправления опубликованных Releases не было.

После объединения PR и проверки сборки необходимо опубликовать тег `radio-agent-v0.3.1` на **проверенном коммите main**; workflow автоматически прикрепит исполняемый файл к GitHub Release. Тег не создаётся автоматически при объединении PR, чтобы не публиковать непроверенную сборку. Затем следует проверить обновление со старой установленной версии 0.2.0.

Если 0.2.0 уже сообщает «Не удалось проверить обновления», этот текст не различает SSL/интернет/API; новая версия выводит конкретную категорию ошибки. Исправить код **уже запущенного 0.2.0** без выпуска и установки нового EXE невозможно. При ошибке GitHub API скачайте проверенный EXE вручную из GitHub Actions или Releases.

**Примечание:** текущая кнопка «Перезапустить обновлённую версию» запускает скачанный и проверенный EXE из каталога updates; она не заменяет старый исполняемый файл на прежнем пути. Для постоянного обновления перенесите проверенную версию в постоянный каталог программы после завершения её работы и перенастройте автозапуск.
