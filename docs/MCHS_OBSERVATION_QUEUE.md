# Очередь наблюдений МЧС (неэфирная)

## Назначение
SafetyMchsQueueItem сохраняет ровно одну запись OBSERVED для каждого SafetyMchsEvent. Транзакция POST /api/safety-ingest/event добавляет событие и запись очереди атомарно. Повторная HMAC-доставка не создаёт вторую очередь и не сбрасывает статус/счётчики.

Миграция создаёт таблицу и разово импортирует исторические события. Очередь **не имеет** обработчика, таймера или worker для воспроизведения. Все поля для последующей обработки являются только диагностическими. Нет подключения к радиоканалу, ESP32 или публичному потоку.

## Проверка после развёртывания
1. Применить обычный deploy проекта с Prisma migration и regenerate client **до** рестарта API. Не запускать db push.
2. GET /api/safety/observation-queue (Bearer ADMIN или safety.view) возвращает последние 30 записей OBSERVED, total и dispatchEnabled:false.
3. Проверить, что повторно доставленное существующее sourceEventId не увеличивает total.
4. Проверить, что очередное реальное уведомление увеличивает total ровно на 1; событие остаётся verified:false.
5. Проверить, что радио и усилитель не реагируют на приём.

В этом этапе нет автоматического продвижения состояний, проверки официального источника или запуска ALARM.
