# Auto-DJ — этап 1: центральный непрерывный эфир

## Назначение

Авто-DJ заполняет **промежутки между утверждёнными передачами** выбранным администратором утверждённым плейлистом. Серверный процесс `server/workers/radioPlayout.js` продолжает выдавать единый MP3 поток через защищённый API. Запланированные передачи всегда имеют приоритет.

Это **пилот**: включение Авто-DJ через интерфейс не разрешает локальный звук, не переводит Radio Agent в PILOT и не управляет усилителем или ESP32. По умолчанию Авто-DJ выключен. Серверный Worker продолжает требовать отдельный флаг `RADIO_PLAYOUT_ENABLED=true` и секрет (см. `docs/RADIO_CONTINUOUS_WORKER.md`).

## Администратор

1. Подготовить и утвердить отдельный музыкальный плейлист (непустой, с валидными аудиофайлами).
2. Открыть **Радио → Главная → Авто-DJ** и выбрать этот плейлист.
3. В тестовом окружении поставить «Заполнять паузы…» и сохранить. Убедиться, что Worker жив, а звук слушается **только через наушники** на разрешённом тестовом приёмнике.
4. Выключить настройку — текущий Авто-DJ трек должен остановиться по проверке состояния приблизительно за 3 секунды плюс время перехода декодера. Запланированный эфир не прерывается.

Восстановление: снять галочку в админке, при необходимости остановить тестовый Radio Worker. Не изменять токены устройства и управление оборудованием.

## Инженерная схема

- `setting.radio_autodj_v1`: `{enabled:boolean,playlistId:string|null}`; никакой миграции таблиц.
- `GET/PUT /api/radio/autodj`: только ADMIN, при активации утверждённый непустой плейлист.
- Один глобальный курсор рассчитан из времени сервера и суммарных длительностей музыки: после перезапуска поток возвращается к вычисленной позиции, не начинает список заново.
- В паузах Worker декодирует файл в уже существующий PCM→MP3 encoder. Начало ближайшего запланированного эфира ограничивает декодирование; дополнительные проверки раз в 3 секунды обнаруживают экстренное отключение Авто-DJ или новый слот.
- Отсутствующий или повреждённый файл временно исключается на 5 минут; Worker пробует следующую доступную композицию, но при полном отсутствии годных файлов остаётся тишина. Периодический контроль уровня сигнала ещё не реализован.
- `GET /api/radio-agent/agent/snapshot` содержит `autoDj: {enabled,playlistId,tracks}`. Загрузка файлов доступна авторизованному агенту только из актуальной утверждённой сетки или активного списка Авто-DJ. Windows и macOS sync-агенты скачивают/проверяют аудио по SHA-256, **не воспроизводят** его.
- `/api/radio-agent/dashboard` и `/agent/now-playing` сообщают статус `AUTO_DJ`, когда нет активного слота; настоящий статус процесса/потока — в `/dashboard/worker`.

## Ограничения этапа 1

- На Windows pilot `pilot_playout.py` прежний режим: проигрывает **только** запланированные слоты, не новый список Авто-DJ. Офлайн-Авто-DJ на Windows — отдельный этап, после проверки центрального потока.
- Не реализованы crossfade, джинглы, музыкальные категории, анти-повторы и loudness normalization.
- При сетевой/БД ошибке Worker может выдавать тишину; гарантированное непрерывное резервирование требует отдельного независимого плейаута, контроля тишины и журналирования.
- Включение Worker/аппаратного выхода **не** автоматизируется этим PR. Никакой работы с PA, реле и ESP32.

## Проверки перед объединением

- `node --check server/workers/radioPlayout.js`, `node --check server/src/routes/radioAgent.js`, `node --check server/src/routes/radio.js`.
- `cd server && npm test -- --run` (команда может зависеть от конфигурации тестов) и frontend build.
- Без активных передач и с Auto-DJ OFF: прежний статус SILENCE.
- Auto-DJ ON с разрешённым плейлистом: Worker AUTO_DJ; аудио идёт в защищённый поток, а не в неразрешённый физический выход.
- Передача начинается через 30 секунд: Авто-DJ не пересекает границу старта, статус переходит в SCHEDULED.
- Новый эфир вставляется, когда играет Авто-DJ; переключение выполняется после проверки.
- Выключение из админки посреди трека, удаление/отзыв утверждения плейлиста, битый или отсутствующий файл, пустая библиотека, сбой БД.
- Agent snapshot, синхронизация macOS/Windows, SHA-256, запрет скачивания произвольных файлов; нет разрешения на громкоговорители.
