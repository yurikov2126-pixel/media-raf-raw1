# PR #1009 — диагностика GPIO13 непосредственно на ESP32

Этот PR добавляет только наблюдение за уже существующими силовыми переходами. Само управление реле Active HIGH на GPIO13, интервал heartbeat 10 секунд, максимальная lease 9 секунд, HMAC, допустимость питания и watchdog не ослаблены.

## Новые поля GET /health

- `relayOnTransitions` и `relayOffTransitions`: монотонные в пределах одной загрузки ESP32 счётчики **изменений командного GPIO13** (повторное продление ON или повторная команда OFF не увеличивают их);
- `lastRelayTransitionMs`: значение `millis()` на момент последнего реально выполненного командного изменения; это **время от запуска**, не UTC;
- `lastRelayOffReason`: последний известный источник команды выключения;
- `lastRelayOnReason`: `SIGNED_POWER_PERMIT`;
- уже существующий `bootNonce` позволяет отличать перезагрузку устройства от простого сброса счётчиков.

Допустимые причины выключения включают `SIGNED_PERMIT_FALSE`, `POWER_INTERLOCK_REJECTED`, `WIFI_RECONNECT`, `WIFI_LOST`, `HEARTBEAT_TIMEOUT`, `POWER_LEASE_EXPIRED`, `SIGNED_MAINTENANCE_RESTART`, `SIGNED_FIRMWARE_UPDATE`, `FIRMWARE_UPDATE_COMPLETED` и `SCHEDULED_REBOOT`. Начальное состояние `BOOT_SAFE_OFF` не считается переключением реле.

Windows Agent уже пересылает исходный JSON `/health`; сервер теперь также сохраняет эти поля, а журнал `mchs_esp32_transition_evidence_v1` сравнивает счётчики **только внутри одного bootNonce**. Два состояния `ON_COMMANDED`, между которыми прошёл короткий цикл OFF→ON, теперь выявляются по росту обоих счётчиков. При смене bootNonce фиксируется `FIRMWARE_REBOOT`, и уменьшение счётчиков не трактуется как дополнительное переключение.

## Ограничения

- Firmware-счётчики фиксируют программное управление GPIO, **не обратную связь** от физического реле или наличие 220 В на AA-300.
- После перезагрузки ESP32 предыдущие локальные счётчики теряются, поэтому на сервере фиксируется отдельный факт смены bootNonce.
- Если Wi-Fi пропал раньше передачи очередного отчёта, известен рост счётчика после восстановления, но точная UTC-метка OFF может быть установлена лишь приблизительно.
- Это не подтверждает отсутствие отключений; проверка только программной команды. Все production-флаги автоматического МЧС-вещания остаются неизменными.
- В этом PR изменены исходники прошивки. Для применения новой телеметрии нужна безопасная прошивка ESP32 на отключённой от 220 В цепи. Компиляция и аппаратная работоспособность должны быть проверены перед применением.

Проверки Node CI: скрытый OFF→ON между опросами, перезагрузка и новая эпоха счётчиков, совместимость со старой ESP32, сохранение прежних событий и запрет ложного объявления физической готовности.
