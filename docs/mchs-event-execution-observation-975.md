# МЧС #975 — подтверждение локального звука события и возврата центрального эфира

После подтверждённых испытаний #974 добавлен обратный канал наблюдения
**от штатного Windows Agent к существующей платформе MEDIA·RAF·RAW**.

Раньше локальное завершение события в режиме `--isolated-event-audio`
печаталось только в консоль. Теперь Agent формирует отдельный
`eventId`-привязанный отчёт после завершения каждого учебного события
и пытается доставить его через:
`POST /api/radio-agent/agent/mchs-event-execution-observation`.

## Что передаём
- `eventId`, `eventType`, `phase` (`COMPLETE` либо `FAILED`);
- `expectedRepeats` и `completedRepeats`;
- `naturalCompletion`: все ожидаемые VLC-повторы завершились;
- `centralReturnConfirmed`: после WAV получены свежие центральные пакеты;
- `processRunning`: остался ли локальный VLC;
- `failureReason`: причина неудачи.

На сервере этот отчёт принимается только от device-auth
`MCHS_AGENT_LAB_DEVICE_ID`, строго нормализуется и сохраняется
в `prisma.setting` отдельно от командного журнала.
`COMPLETE` возможен только при естественном завершении всех
повторов, прекращении локального VLC и подтверждённом возвращении
центрального потока. Отчёт не меняет состояние тревоги и не разрешает
новую тревогу.

**Ни один отчёт не является подтверждением физической трансляции.**
Сервер фиксирует `localProcessObservationOnly:true`,
`physicalPaOutputVerified:false`,
`publicPlaybackAuthorized:false`.

## Проверка

1. Сохранить физически отсоединёнными AA-300/PA, использовать наушники.
2. После объединения PR #975 скачать полный исходный комплект
   `main.zip` и запустить уже проверенный режим #974:
   `central_playout.py --enable-headphones-test --isolated-event-audio`
   с аргументами локальных WAV, VLC и `RADIO_AGENT_TOKEN`.
3. Использовать только безопасные авторизованные **учебные** серверные
   события с SHA-256 этих двух WAV (если сервер их предоставляет).
   Не создавать реальную тревогу ради испытания.
4. При удачном локальном завершении искать журнал:
   `MCHS_EVENT_AUDIO_RESULT` и
   `MCHS_EVENT_OBSERVATION_ACCEPTED <eventId> COMPLETE`.
   При сетевой ошибке — `MCHS_EVENT_OBSERVATION_RETRY`.
5. Для проверки серверного наблюдения администратор может сверить
   запись ключа `mchs_agent_event_execution_observation_v1_<deviceId>`
   в существующих settings. Сам `deviceId` и токен не публиковать.

Отправка best-effort с повторными попытками внутри процесса Agent.
Если компьютер выключится до подтверждения доставки, очередь в памяти
потеряется — поэтому в этом PR НЕ объявляется exactly-once delivery.
Не следует приравнивать серверное наблюдение к акустическому выходу.

## Что ещё не включено

Режимы по умолчанию, реальные Android уведомления, программное
управление публичным Worker, ESP32 и усилителем не изменяются.
Испытание PA/здания требует отдельной процедуры.
