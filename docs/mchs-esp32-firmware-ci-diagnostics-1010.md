# PR #1010 — проверка прошивки ESP32 и диагностика основного тракта в админке

## Проверка firmware в CI

GitHub Actions CI теперь включает отдельное задание `esp32-firmware`: чистая Ubuntu, Python 3.12, PlatformIO 6.x и компиляция `radio-agent/esp32/platformio.ini` для `esp32dev`. Перед компиляцией создаётся **только для runner** локальный `include/secrets.h` копированием `secrets.example.h` с заглушками. Секреты production не используются и в репозиторий не публикуются. Задание **не прошивает устройство** и не выдаёт firmware binary для автоматической установки.

Сборка является отдельным требованием проверки PR: Node-тесты счётчиков не способны выявлять ошибки компилятора C++ и линковки ESP32.

## Экран «Тракт оповещения»

`client/src/pages/Admin/tabs/MchsTransportStatus.jsx` переведён с лабораторного VLC, старых START/STOP и isolated-состояний на проверку реального исполнительного контура. Каждые 15 секунд он **только читает** существующие защищённые административные маршруты:

- `GET /safety/missile-main-station-readiness`: Worker, terminal journal, Windows Agent, ESP32 и причины `HOLD`;
- `GET /safety/missile-android-execution-intents`: очередь ALARM и ALL-CLEAR;
- `GET /safety/missile-station-execution-receipts`: факты приёма START и PCM-исполнения;
- `GET /safety/missile-live-trial-preflight`: назначенные аудиофайлы и число повторов.

В блоке GPIO13 видны счётчики ON/OFF, последняя записанная причина выключения и история переходов ESP32 за 10 минут; причины переведены на русский. Для старой прошивки без счётчиков выводится отдельное предупреждение. Сохраняется ручная кнопка «Обновить», адаптивные карточки и ограничения физической слышимости.

## Точки контроля

- Даже при `ON_COMMANDED` или нулевом числе переходов интерфейс **не** подтверждает стабильность питания AA-300 или наличие звука в коридорах. Точное питание и акустическая слышимость требуют независимого измерения.
- Время переходов в ленте — время наблюдения по серверным снимкам, не физическая UTC-метка контактов реле. Короткий OFF→ON виден через firmware-счётчики только после обновления прошивки и получения телеметрии Agent.
- CI-компиляция и веб-сборка должны быть зелёными **до** объединения. Firmware не обновляется автоматически этим PR.
- Управление реле, watchdog и HMAC, Windows Agent аудиотракт, правила MCHS и флаги активации реального эфира не меняются.

Следующее испытание: установить проверенный firmware при отключённой силовой нагрузке, затем прочитать лог `power-diagnostics.log` и `lastRelayOffReason` при безопасном воспроизведении без подключения PA.
