# Windows Radio Agent — центральный эфир и локальный резерв (тест)

## Что нового

`radio-agent/windows/central_playout.py` — отдельный opt-in тестовый клиент:
- читает защищённый центральный MP3 поток через локальный HTTP relay на `127.0.0.1`;
- при потере потока переключается на локальные файлы из `sync_agent.py`, проверенные SHA-256;
- резервный выбор всегда отдаёт приоритет утверждённому расписанию и только затем Auto-DJ;
- при восстановлении потока останавливает локальный VLC прежде, чем запускает центральный, избегая параллельного звука;
- периодически получает разрешение `/agent/status`, обрывает звук при 401/403, отзыве разрешения или истечении 15 минут отсутствия подтверждения (по умолчанию);
- **не** включает усилитель, реле, ESP32, радиоаппаратуру или автозапуск Windows. Нет изменения существующего `pilot_playout.py`.

## Запуск — только на тестовой Windows-машине и с наушниками

Сначала убедитесь, что администратор отдельно разрешил PILOT для этого RadioDevice, установлен VLC и заданы `RADIO_AGENT_TOKEN` и HTTPS URL. Отключите акустическую систему и PA от физического выхода.

В папке `radio-agent/windows`:

```powershell
$env:RADIO_AGENT_TOKEN = "rr_...ваш_локальный_секрет..."
python .\sync_agent.py --server https://mediarafraw.ru --data-dir radio-agent-data --once
python .\central_playout.py --server https://mediarafraw.ru --data-dir radio-agent-data --vlc "C:\Program Files\VideoLAN\VLC\vlc.exe" --enable-headphones-test
```

Не записывайте токен в репозиторий, чат или публичные логи. После запуска VLC проигрывает звук через **устройство Windows по умолчанию**; убедитесь, что это **наушники**, до старта программы.

Прерывание: `Ctrl+C` в терминале; при необходимости закройте дочерние VLC вручную. В админке снимите разрешение на тестовое воспроизведение.

## Проверки

1. Центральный поток работает: отображается `PRIMARY_CONNECTING`, VLC получает MP3; контролируйте через наушники.
2. Прервать сеть в тестовом сегменте: ожидается `LOCAL_STANDBY` и `LOCAL_TRACK` при доступном проверенном кеше.
3. При восстановлении соединения возвращается центральный поток.
4. Повреждённый/отсутствующий резервный файл — звук не запускается из произвольного файла.
5. Снятие разрешения PILOT — воспроизведение прекращается; при полном отсутствии сети действует ограничение `--offline-grace` (по умолчанию 900 секунд).
6. Проверить переключение на границе запланированной передачи и Авто-DJ.
7. Проверить `python -m unittest test_standby_plan.py`.

## Ограничения

Это **пилот**, а не готовая к круглосуточной PA-эксплуатации система: прослушивание через наушники, без контроллера звука, нормализации, автоматического запуска и гарантированного бесшовного перехода. Интервал восстановления может содержать короткую паузу; HTTP сигнал сам по себе не доказывает слышимость аудио. Для продакшена потребуется проверка аппаратного выхода, переключения источников, heartbeat и отдельной политики безопасного отключения.
