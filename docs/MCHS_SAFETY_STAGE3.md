# MCHS Stage 3 — HMAC transport (staged, off by default)

Это **экспериментальный** входящий API для наблюдений Android, не сертифицированный канал тревог. Ничего в системе вещания не запускает.

## Включение
* `POST /api/safety-ingest/event` — машина-машина, НЕ пользовательский JWT.
* По умолчанию `MCHS_INGEST_ENABLED` отсутствует → HTTP 503; даже если ключ установлен.
* На выделенном **preview** сервере задать `MCHS_INGEST_ENABLED=true` и **уникальный** случайный `MCHS_INGEST_HMAC_KEY` (не менее 32 символов), только через секреты окружения, не коммитить.
* Продакшен оставлять отключённым до испытаний. Ограничить маршрут на nginx по IP/VPN и частоте запросов; использовать HTTPS и ключ отдельно для каждого окружения.
* Важно: подпись HMAC подтверждает владение ключом шлюза, а **не подлинность государственного сообщения**. `verified=false` всегда, автоматических команд нет.
* Запросы JSON не более 16 KiB; timestamp за пределами ±120 секунд отклоняется. Применяется HMAC SHA-256 по **UTF-8 timestamp + "." + точные байты JSON**. Header: `X-MCHS-Timestamp: <unix seconds>`; `X-MCHS-Signature: sha256=<lowercase hex>`.
* Body: `{ "eventId": "device-event-uuid", "title": "текст", "body": "сообщение", "channelId": "emercom_channel", "region": "Тульская область", "occurredAt": "2026-10-26T17:00:00.000Z" }`
* Возврат: `200 {accepted:true,...,verified:false,testOnly:true}`. Повторы `source+eventId` идемпотентны. Для настоящей поставки событий нужен Android sender с локальной устойчивой очередью и подтверждениями.
* **Уведомления, собранные на Android до установки отправителя, автоматически не попадут в базу сайта**. Их историю нужно экспортировать отдельно, если она сохранилась.

## Проверки перед merge / deployment
1. На preview применить миграции из этапа 2, `npx prisma generate`, затем API + client build.
2. Без переменных: 503. С неверной подписью: 401. Устаревшее время: 401; слишком большой payload: 413; некорректный JSON: 400.
3. Дважды отправить одну корректно подписанную тестовую запись: число в БД увеличивается только на 1.
4. Проверить `GET /api/safety/dashboard` / `events` под ADMIN, `safety.view`, обычным студентом (403).
5. Проверить, что режим оповещения нельзя активировать ни в UI, ни через API.
6. После отключения тестового приёма `MCHS_INGEST_ENABLED=false` новый POST снова 503.

## Не включено
* Ни heartbeat, ни фактическое доказательство доставки FCM; статус соединения остаётся NOT_CONFIGURED.
* Ни проверки официального происхождения сообщений, ни классификации опасности.
* Ни команд прерывания радио, ни управления звуковым оборудованием.
* Ни синхронизации истории Android. Всё это — отдельные этапы с проверками.

Для испытаний не используйте текст, похожий на реальную чрезвычайную тревогу, и не публикуйте чувствительные детали.
