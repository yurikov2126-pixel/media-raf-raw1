# PR #1025 — физический тракт МЧС: запрос питания при реальном PCM ALARM

## Наблюдаемая неисправность

При настоящей ракетной опасности основной Radio Worker передал ALARM в /radio/live и Windows Agent, но AA-300 не включился. В `radioAgent.js` решение `ampDecision()` в AUTO опиралось лишь на сетку расписания или Auto-DJ. Активная реальная приоритетная МЧС-сессия не учитывалась; когда музыка в обычном расписании не запрашивала питание, сервер возвращал `permit:false`.

## Изменение

- API запрашивает существующий авторизованный `GET /mchs-station-session` у локального Worker с тем же общим секретом.
- Только **активная PCM-сессия** с `eventType=MISSILE_DANGER` или `MISSILE_ALL_CLEAR`, корректным `eventId`, `phase=PREEMPTING/PLAYING`, `active:true` и `enabled:true` даёт дополнительное основание поддерживать питание в **AUTO**.
- Для такого случая `GET /agent/amplifier-intent` возвращает отдельный `policyMode:MCHS`, `reason:Основное оповещение МЧС` и `mchsEventId`. Это не подменяет ручной режим и не создаёт команд из самого Android-уведомления.
- Windows Agent подтверждает явное разрешение MCHS без зависимости от кнопки запуска обычной музыки и аудио-таймера, **но** требует авторизованный серверный `permit:true`, точный IP ESP32, `POWER_CONTROL_V1`, включённый оператором аппаратный допуск и не-изолированный режим.
- `emergencyOff:true` и явное ручное `MANUAL OFF` сохраняют абсолютный приоритет. После завершения файла Worker прекращает заявлять `active`, и в AUTO возвращается обычная политика сетки/AutoDJ.
- Обрыв авторизованного Worker STATUS или неактивная сессия не создаёт новое разрешение на питание. Физический GPIO13 по-прежнему регулируется HMAC, lease и watchdog.

**Ограничение:** первый серверный запрос об активном PCM произойдёт после начала подготовки аудиофайла. Это не обещает включить усилитель заранее до первого звукового семпла. Для полной аппаратной верификации необходимо последующее измерение синхронности в безопасно изолированном контуре. Подтверждение программного `permit:true` не эквивалентно наличию 220 В или слышимости колонок.

## Развёртывание

Изменены **и API, и Windows Agent EXE**. Установка одного только API не исправит локальный audio gate старого Agent. Требуются развёртывание backend и обновление Agent; ESP32 прошивать не требуется. Не воспроизводите фиктивную ракетную опасность через production-мост. При необходимости исследуйте оригинальное прошедшее событие по существующему журналу, без повторной трансляции.

## PUSH

Этот PR не повторяет прошедшие PUSH и не изменяет PR #1024. Для расследования проверьте действующую версию API, наличие миграции `SafetyMchsPushDelivery`, наличие ряда по прошедшему реальному событию, `MCHS_PUSH_DELIVERY` в журнале API, заполнение Web Push VAPID и (для нативного Android) Firebase/FCM. Не публикуйте ключи, токены, адреса подписчиков. Отсутствие подтверждений от провайдеров следует устранить отдельно от цепочки усилителя.
