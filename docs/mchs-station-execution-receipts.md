# PR #1002 — подтверждение PCM-исполнения МЧС

Сервер сохраняет event-bound результаты отправки нового Android-события в `mchs_station_execution_receipts_v1`. При штатном 15-секундном цикле монитор получает внутренний `GET /mchs-station-session` (без запуска звука) и обновляет запись **только для совпадающего eventId**.

Фазы:
- `START_ACCEPTED` — Worker подтвердил приём команды; **не подтверждение слышимого звука**;
- `PLAYING` — Worker зафиксировал замену PCM;
- `RESUMING` — PCM-файл доигран полностью с необходимым количеством повторений;
- `COMPLETE` — также подтверждено восстановление ненулевого PCM обычной программы;
- `FAILED` / `INCOMPLETE_EVIDENCE` — ошибки и недостаточные доказательства.

Новая защищённая ролью ADMIN read-only ручка `GET /safety/missile-station-execution-receipts` (реальный префикс определяется маршрутизатором Express) возвращает журнал и явный признак `physicalOutputConfirmed:false`. Команда STOP при естественном завершении по-прежнему не нужна.

## Границы

Все три флага реального запуска остаются выключенными по умолчанию, они не меняются этим PR:
`MCHS_ANDROID_MAIN_STATION_DISPATCH_ENABLED`,
`MCHS_MAIN_STATION_COORDINATOR_ENABLED`,
`RADIO_MCHS_STATION_COMMANDS_ENABLED`.

Монитор фиксирует только снимки Worker в момент опроса, поэтому кратковременные промежуточные состояния могут быть пропущены; терминальный снимок следующего события может заменить предыдущий. Реализованный текущий receipt ledger не является полной гарантией журналирования при сбое процесса между ответом START и транзакцией сохранения. Нужны отдельные долговременные event-bound события Worker и защитная обработка параллельных событий. Отсутствие Worker или ненаблюдаемое завершение не считается успехом.

Доказательство PCM на входе энкодера **не доказывает фактическую слышимость** в браузере, Windows Agent или колонках AA-300. Динамическое включение ESP32, аппаратная готовность и устранение OFF/ON по-прежнему отдельные задачи. Не включать флаги до интеграционной приёмки.
