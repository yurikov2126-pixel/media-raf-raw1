# Радио 2.0 — часовой пояс станции

## Что сделано
- Сервер интерпретирует `startLocal` как локальное время станции в `Europe/Moscow` (UTC+03:00).
- Повторы по дням недели рассчитываются в часовой зоне радиостанции, а не UTC.
- В браузере недельная сетка и часы эфиров выводятся по `Europe/Moscow`, независимо от часового пояса телефона или ПК администратора.
- Для обратной совместимости API ещё принимает старое поле `startAt` с ISO-дата-временем.
- Эта версия **не** запускает физическое вещание, Windows Agent или ESP32.

## Установка на Ubuntu 24.04 + aaPanel
Новых системных пакетов, npm-модулей и миграций Prisma не требуется. Используется встроенный Intl Node.js. ffprobe уже установлен: /usr/bin/ffprobe.
После успешной сборки и review примените штатный production deploy с резервным копированием БД, не меняя вручную настройки nginx и aaPanel.

## Проверки перед слиянием
1. Открыть календарь под устройством в Europe/Moscow, создать эфир на завтра в 10:00.
2. Открыть тот же эфир на устройстве Europe/Berlin: должно показываться 10:00 по Москве, а не локальные часы устройства.
3. Создать повтор по понедельникам в 09:00 на три недели. Все слоты должны приходиться на понедельник в 09:00 по Москве.
4. Убедиться, что пересечения по-прежнему блокируются транзакционно (409).
5. Проверить существующие слоты: UTC instants не меняются в базе; изменяется только **отображение** в часовом поясе станции. Для слотов, ранее ошибочно созданных с локального браузера, фактический час может потребовать ручной коррекции после сверки.
6. Проверить, что API /api/radio/status отдаёт timezone Europe/Moscow.
7. Проверить запрет STUDENT на /api/radio и отсутствие команд аппаратуре.
