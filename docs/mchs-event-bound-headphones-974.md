# МЧС #974 — выполнение серверного события в ИЗОЛИРОВАННЫХ наушниках Windows Agent

После #972 (реальное переключение центрального звука) и #973
(валидация и защита от повторов) Agent получил отдельный **явно
включаемый оператором** режим event-bound учебного звука.

Это не выпуск для общественных громкоговорителей и не автоматическое
включение реальной МЧС-тревоги.

## Условия допуска

- Все аудиолинии AA-300/PA **физически отсоединены** и подключены наушники.
- Закрыт другой экземпляр Windows Radio Agent: одновременно работающие
  программы могут создавать наложение звука.
- Устройство авторизовано с токеном `RADIO_AGENT_TOKEN`.
- Оператор запустил Agent вручную с `--isolated-event-audio` и ввёл
  `ISOLATED`. Стандартный запуск Agent **не включает этот режим**.
- На компьютере два разных подготовленных учебных PCM16 WAV с разрешённой
  длительностью и форматами. Эти файлы проверяются до подключения.
- Серверный `mchs-execution-command` содержит свежий START с
  `officialSourceVerified=true`, `executionEnabled=true`, `halted=false`,
  допустимым числом повторов, валидным eventId и SHA-256, **совпадающим**
  с локальным учебным WAV соответствующего типа.
- Центральный VLC должен воспроизводить авторизованный поток с новыми
  пакетами. Без центрального аудио переключение не выполняется.

Команды обслуживаются лишь в этом операторском режиме, по HTTPS с
устройственным токеном; никакой внешний URL аудио из команды не открывается.
`assetId` не выбирает произвольный локальный путь. Путь к WAV закрепляет
оператор, SHA-256 привязывает серверную команду к его содержимому.

## Запуск

Скачайте актуальный полный `main.zip` после объединения PR и распакуйте в
отдельную папку (для этого Git не требуется). Из папки
`radio-agent/windows`:

```powershell
$secureToken = Read-Host "Windows Radio Agent device token" -AsSecureString
$env:RADIO_AGENT_TOKEN = [System.Net.NetworkCredential]::new("",$secureToken).Password

py .\central_playout.py `
  --vlc "C:\Program Files\VideoLAN\VLC\vlc.exe" `
  --enable-headphones-test `
  --isolated-event-audio `
  --isolated-event-danger-wav "C:\MchsTest\alarm_missile_start_pcm16.wav" `
  --isolated-event-all-clear-wav "C:\MchsTest\alarm_missile_end_pcm16.wav"
```

Для дальнейшего теста нужны **реальные авторизованные серверные
учебные команды**, у которых SHA-256 точно совпадает с выбранными
локальными файлами. **Не включайте действующую МЧС-тревогу ради теста.**
Если таких безопасных тестовых команд сервер ещё не создаёт, режим
будет ждать; это правильный отказ, а не проблема WAV.

Для сравнения SHA-256:
```powershell
Get-FileHash "C:\MchsTest\alarm_missile_start_pcm16.wav" -Algorithm SHA256
Get-FileHash "C:\MchsTest\alarm_missile_end_pcm16.wav" -Algorithm SHA256
```
Хеш — не секрет, но сам `RADIO_AGENT_TOKEN` в журнал не включайте.

## Поведение одного события

1. START проверяется существующим валидатором и `EventAdmissionLedger`.
   Повтор события после перезапуска не воспроизводится.
2. Agent останавливает собственные `primary` и `fallback` VLC,
   затем запускает локальный WAV нужного типа ровно `repeats` раз.
3. Результат `COMPLETED` требует естественного выхода VLC с каждым
   повтором и полного совпадения `eventId`.
4. После события новый центральный VLC подключается, а
   `CentralReturnMonitor` требует поступления **свежих аудиопакетов**.
5. Для отбоя нужна ранее зафиксированная опасность. Следующее событие
   можно принять после подтверждённого возврата эфира.
6. STOP или HALT прерывают текущий учебный WAV; подтверждение остановки
   требует фактического завершения дочернего VLC-процесса.
7. При ошибке источника, повтора, тайм-ауте, потере авторизации или
   отсутствии центральных пакетов фиксируется причина отказа; статус
   акустического PA **никогда** не подтверждается.

## Метки журнала

`MCHS_EVENT_BOUND_HEADPHONES_ONLY`,
`MCHS_EVENT_AUDIO_START`,
`MCHS_EVENT_AUDIO_COMMAND`,
`MCHS_EVENT_AUDIO_STOP_EVIDENCE`,
`MCHS_EVENT_AUDIO_RETURN_ARMED`,
`MCHS_CENTRAL_RETURN_CONFIRMED`,
`MCHS_EVENT_AUDIO_RESULT`.

Результат имеет `physicalPAConfirmed:false` и
`publicPlaybackAuthorized:false` всегда. **Это локальный отчёт, не
подтверждение того, что звук услышали люди в здании.**

## Границы PR

- Не создаёт новые серверные события и не включает Android-автоматику.
- Не посылает управляющие команды на Worker, в публичный эфир, ESP32,
  AA-300 или PA.
- Не изменяет серверный протокол и административные настройки.
- Не является полноценной телеметрией физического оповещения; серверный
  журнал обязан отличать локальные учебные receipts от фактического PA.
- При повреждении `mchs-event-admission.json` режим отказывает в
  старте до ручной диагностики, не стирая историю.
- После проверки остановите Agent Ctrl+C и удалите токен:
  `Remove-Item Env:\RADIO_AGENT_TOKEN -ErrorAction SilentlyContinue`.
