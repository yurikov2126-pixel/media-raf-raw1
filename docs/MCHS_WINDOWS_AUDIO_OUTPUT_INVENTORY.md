# МЧС: инвентаризация отдельного выхода Windows Agent

Штатный Radio Agent продолжает работать. Существующий лабораторный
`mchs_isolated_output_pilot.py` воспроизводит аудио через системный
выход Windows **по умолчанию** и поэтому **не подходит** для одновременного
испытания при подключённом основном тракте PA.

Для следующего этапа добавлен пассивный осмотр аудиоустройств Windows:

```powershell
cd radio-agent/windows
py mchs_audio_device_inventory.py
```

Команда показывает перечень доступных выходов старого Windows waveOut API,
их индекс, имя и количество каналов. Аудио не открывается и не воспроизводится.
Отдельный выход НЕ выбирается и не привязывается к VLC автоматически.

**Ограничение:** названия и индексы waveOut не являются надёжными
идентификаторами современных WASAPI endpoint GUID. Даже два разных имени
не доказывают физическую независимость от AA-300 и коридорного PA.
Поэтому флаги `separateOutputConfirmed`,
`physicalIsolationVerified`, `playbackAuthorized` всегда `false`.

Перед следующим PR потребуется обеспечить адресное воспроизведение
по устойчивому идентификатору WASAPI endpoint, измерение раздельного
звукового пути и подтверждение физического отсоединения PA.
Не запускать старый пилот через Windows DEFAULT выход при работающем
усилителе. Статус `OBSERVE_ONLY` не подтверждает аварийное переключение.
