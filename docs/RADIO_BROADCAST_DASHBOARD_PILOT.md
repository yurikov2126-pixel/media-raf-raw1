# Radio 2.0 — серверный аудиотранспорт и вещательный Dashboard (пилот)

## Добавлено
- Серверный endpoint `GET /api/radio-agent/agent/stream-pilot`, авторизация **токеном радиокомпьютера** (Bearer), только если в админке разрешён PILOT. FFmpeg декодирует утверждённый текущий трек с позиции глобального эфирного курсора и отдаёт MP3 48 кГц, 128 кбит/с по HTTP.
- Загрузка аудиофайлов и их приватность не изменяются, наружу не открывается файловый каталог.
- Ограничено до 3 одновременных пилотных запросов.
- `GET /api/radio-agent/dashboard` — только ADMIN JWT: состояние HTTP-передачи, актуальный курсор, активные устройства, ближайшие запланированные слоты, ошибки.
- Новый вещательный Dashboard **над существующими карточками** на домашнем экране Радио. Автообновление раз в 5 секунд, адаптация под мобильные устройства, обе темы. Существующие разделы не удаляются.

## Важно: что ещё не сделано
Это **первый пилотный серверный транспорт, не круглосуточная радиостанция**:
- Каждый подключившийся радиокомпьютер получает отдельный FFmpeg-процесс; **единого фонового worker/общего кодированного потока ещё нет**.
- Этот endpoint выдаёт аудио только до конца **текущего трека** или слота. Подключение к следующему треку и непрерывная передача требуют следующей итерации.
- Текущий WebRTC-прямой эфир с телефона на Mac остаётся **отдельным**. Серверного микширования и приоритета ведущего в этом PR нет.
- Mac/Windows Radio Agent ещё **не переключён на этот HTTP-поток**, автоматический failover к локальному кэшу ещё не реализован.
- `lastSeenAt` устройства подтверждает лишь запрос к API, но не наличие слышимого звука.
- Никакого управления AA-300/ESP32 и аварийными объявлениями.

## Ubuntu Server 24.04 / aaPanel
На сервере требуется бинарник `ffmpeg` с `libmp3lame`:
```bash
command -v ffmpeg
ffmpeg -hide_banner -encoders | grep libmp3lame
```
При необходимости: `sudo apt update && sudo apt install ffmpeg`.
Переменные окружения: `RADIO_ASSET_DIR` (существующая приватная библиотека), опционально `RADIO_FFMPEG_PATH` (путь к бинарнику).
Штатный деплой Node API и сборка React-клиента. Не нужны Prisma-миграции, новые npm-зависимости, новый reverse-proxy маршрут.
Не публиковать токен устройства в URL / query и не открывать тестовый endpoint без аутентификации. Не подключать к усилителю.

## Диагностика
Сначала проверить на тестовом radiodevice с включённым PILOT и при наличии текущей передачи, что `/agent/stream-pilot` отдаёт `Content-Type: audio/mpeg`. Использовать заголовок `Authorization: Bearer <токен>`; токен не сохранять в скриншотах или журналах.
Проверить Dashboard на компьютере и телефоне, индикаторы при отсутствии расписания и при ошибке API.
Тестировать потоки и качество звука без усилителя.
