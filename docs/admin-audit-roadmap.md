# Админка Media_РАФ_RAW — аудит и план обновления

Дата первичного аудита: 2026-10-11. Основание: анализ исходников ветки main, **без доступа к авторизованной production-сессии и без end-to-end тестирования**. «Есть интерфейс/API» не означает «проверено работает».

## Карта разделов (18)

- Обзор: Дашборд, Аналитика, История действий.
- Люди и модерация: Модерация, Пользователи, Восстановление.
- Контент: Курсы, Практики и ДЗ, Wiki, Сертификаты.
- Коммуникации: Рассылки, Push-уведомления.
- Платформа: Дизайн сайта, Модули, Геймификация, Пакетные действия.
- Система: Бэкапы, Настройки.

Каждый раздел подключён в `client/src/pages/Admin/index.jsx`. Доступ к /app/admin ограничен ролью ADMIN в `client/src/App.jsx`. Бэкенд подключён через `server/src/routes/admin.js` → `admin/index.js`.

## Подтверждено анализом исходников

1. Главная панель вызывает `/admin/stats`, `/admin/dashboard/summary`, `/admin/server/info`, `/admin/maintenance/scan`; интерфейс позволяет запускать очистку логов, старых бэкапов и обслуживание БД. Эти операции требуют особенно тщательного ручного теста.
2. Аналитика имеет общие показатели и воронку по курсам.
3. Раздел бэкапов предоставляет создание, скачивание, удаление и восстановление БД. Сам факт успешного восстановления и полнота резервной копии **не подтверждены**.
4. Push содержит управление подписками, отправку и параметры автоочистки; отправку реальным пользователям во время проверки не запускать.
5. В исходном коде загрузка пяти базовых API в Admin/index.jsx скрывала ошибки через `.catch(() => {})`, из-за чего интерфейс мог выглядеть пустым без объяснения. В текущем PR добавлено сообщение об ошибках.
6. На production API запущен через `mediaraf-api.service` от пользователя `www`, однако виджет сервера ориентирован на «Логи PM2». Нужна отдельная проверка backend-источника, прежде чем менять логику мониторинга.
7. Новое редакционное хранилище `/www/wwwroot/mediaraf-storage/editorial` находится вне стандартного uploads. Нельзя считать его включённым в существующие бэкапы без проверки backend-реализации.

## Приоритетный ручной тест (на тестовых данных)

- Авторизация ADMIN, открытие всех 18 вкладок; нет ли ошибок в браузерной консоли или HTTP 4xx/5xx.
- Пользователи: поиск, роли, ограничения прав, безопасное редактирование тестового пользователя.
- Модерация: поступление жалобы, смена статуса и уведомления.
- Курсы / Практики / Wiki / Сертификаты: CRUD тестового контента и доступность результата обычному пользователю.
- Рассылки / Push: проверка целевой аудитории и тестовой отправки только на тестовый аккаунт.
- Модули: переключение тестового модуля и откат, проверка доступа на backend.
- Геймификация: сохранение правил и начисление наград на тестовом аккаунте.
- Дизайн сайта: предпросмотр, сохранение, возврат исходного вида.
- Бэкапы: проверка состава архива и сценария восстановления **только в изолированной среде**, не на production.
- Пакетные действия / обслуживание: сначала dry-run, если поддерживается; массовое удаление и очистку на production не запускать.
- Система: проверить, что мониторинг отражает systemd и реальные постоянные каталоги.

## Рекомендации

**Сохранить:** пользователей, модерацию, курсы, Wiki, настройки модулей, аудит действий, бэкапы.

**Упростить:** убрать техническую очистку с первой страницы в «Система»; объединить близкие разделы аналитики и статистики в понятные вкладки, не удаляя функции; уменьшить количество одновременно отображаемых пунктов навигации.

**Проверить востребованность перед удалением:** «Пакетные действия», отдельная страница «Практики и ДЗ», часть шаблонов оформления, неиспользуемые инструменты push. Удаление требует анализа API и зависимостей.

**Добавить:** диагностику состояния сервисов и хранилищ, отчёт о свежести резервных копий БД и файлов, контроль ошибок API, журнал критичных административных операций и защиту опасных действий подтверждением.
