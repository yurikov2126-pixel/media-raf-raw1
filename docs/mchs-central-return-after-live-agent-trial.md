# МЧС #968 — подтверждение возвращения центрального потока Windows Agent

PR добавляет **только наблюдение** возвращения аудио после уже
существующей изолированной учебной PCM-сессии в `central_playout.py`.

- Счётчик `relay.packet_count` увеличивается **только после отправки**
  очередного блока центрального потока в локальный VLC.
- Когда учебный VLC остановлен и его завершение подтверждено, монитор
  запоминает момент окончания и счётчик пакетов.
- Успех фиксируется только при работающем основном VLC, без ошибки
  Relay, и при поступлении **новых блоков** после момента окончания
  учебного воспроизведения.
- По истечении 30 секунд без подтверждения выводится
  `MCHS_CENTRAL_RETURN_UNCONFIRMED` (или `LOCAL_RESERVE_ONLY`).
- Программное подтверждение не доказывает слышимость в наушниках/PA.

Журнальные метки: `MCHS_CENTRAL_RETURN_MONITOR_ARMED`,
`MCHS_CENTRAL_RETURN_CONFIRMED`,
`MCHS_CENTRAL_RETURN_UNCONFIRMED`.

## Испытание

Только после физического отключения AA-300 и всех альтернативных
выходов PA запустить штатный Windows Agent, разрешённый учебный
аудиотест и проверить журнальные метки после его завершения.
Работающий `/radio/live` не должен воспроизводить учебное
сообщение. Если оно появляется там, испытание остановить.

Сбор и анализ диагностических сведений не запускают ALARM,
не подключают Android-события, не отправляют управляющие команды
в Worker, Agent или ESP32. Не проверяются полные повторения
двухканального оповещения и акустическая слышимость громкоговорителей.

Тест:

```powershell
cd radio-agent/windows
python -m unittest -v test_mchs_central_return_monitor
```
