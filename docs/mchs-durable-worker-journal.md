# PR #1004 — постоянная история завершений МЧС в Radio Worker

Проблема: история терминальных PCM-событий из PR #1003 находилась только в RAM Worker. При его рестарте результаты, не прочитанные серверным монитором за 15 секунд, исчезали.

## Реализация

- При переходе приоритетного PCM-исполнителя в `COMPLETE` (после полного файла, заданных повторов и восстановления нормального PCM) либо в `FAILED` Worker **синхронно добавляет** event-bound JSONL-запись на диск и вызывает `fsync`.
- Worker при следующем запуске загружает этот файл, проверяет записи и отдаёт последние 128 событий через авторизованный `GET /mchs-station-session` вместе с `terminalJournal.healthy`.
- API использует уже существующий `reconcileStationReceiptHistory` и обновляет журнал, даже когда текущая Worker-сессия другая.
- Тот же `eventId` нельзя повторно выполнить после перезапуска Worker, если он зарегистрирован в журнале.
- При ошибке чтения, повреждённом JSONL или ошибке записи новый START блокируется, а API **не признаёт** недоказанный успех в журнале. Существующее радио продолжает играть.

## Настройка

Укажите в окружении `mediaraf-radio-playout.service` абсолютный путь к постоянному диску:
`RADIO_MCHS_TERMINAL_JOURNAL_PATH=/var/lib/mediaraf/mchs-station-terminal.jsonl`

Каталог должен быть доступен для записи пользователю Worker. При отсутствии настройки используется относительный к рабочему каталогу процесса путь `private/mchs-station-terminal.jsonl` (не рекомендуется, если release-каталог очищается при деплое). Не очищайте этот файл при деплое и не переносите путь без переноса старого журнала. Включение новых аудиовыходов или GPIO этим PR не производится.

## Границы

Эта реализация **не** является распределённым transactional outbox. Если процесс погиб до создания терминального события, факт полноценного окончания не может быть восстановлен. Файл не имеет автоматической компакции: предусмотрите контроль объёма, резервную копию и последующую политику retention. Синхронный `fsync` в редком терминальном переходе может создать небольшую задержку аудиотракта; это требует отдельного измерения на production hardware. Текущее подтверждение — PCM в энкодере, не фактическая слышимость в браузере, Windows Agent или в залах.

Остаются выключенными по умолчанию `MCHS_ANDROID_MAIN_STATION_DISPATCH_ENABLED`, `MCHS_MAIN_STATION_COORDINATOR_ENABLED` и `RADIO_MCHS_STATION_COMMANDS_ENABLED`. Не включать их одновременно до безопасной проверки сквозной передачи, устойчивости усилителя AA-300 и согласования с Windows Agent/ESP32.
