# Политех-FM — проверка часового объявления (PCM)

> Статус: сценарий для **изолированного** теста после успешных CI и ревью. Не включать флаги в действующем эфире только на основании слияния PR.

## Обязательные предварительные проверки

1. Убедиться, что текущая ветка содержит изменения `radioHourlyPcmBounds.js`.
2. `cd server && npm ci && npm test -- radioHourlyPcmBounds.test.js radioHourlyPcmIntegration.test.js radioHourlyHandover.test.js radioScheduledHourlyCursor.test.js radioScheduledHourlyResume.test.js`
3. `node --check workers/radioPlayout.js` из каталога `server`.
4. Запустить **отдельный** playout с изолированным источником и без маршрутизации в публичный эфир. Подготовить 24 записи `TIME_SIGNAL` и убедиться, что preflight выбранного часа возвращает `ok:true`.
5. Не менять флаги production до успешного анализа логов и аудиозаписи тестового потока.

## Сценарии, подлежащие прослушиванию

| # | Контекст | Ожидаемый результат |
|---|---|---|
| 1 | AutoDJ, остаток 30 секунд | Песня до конца, затем одна часовая запись, следующая композиция с 0 |
| 2 | AutoDJ, остаток 61 секунд | Fade, одна запись, следующая композиция с 0 |
| 3 | Scheduled, остаток 30 секунд | Песня до конца, одна запись, следующий трек с 0 в пределах слота |
| 4 | Scheduled, остаток 180 секунд | Fade, одна запись, следующий трек с 0 в пределах слота |
| 5 | Crossfade уже смешивает два источника | Crossfade уступает часовому сигналу, нет хвоста второй деки |
| 6 | LIVE включается перед объявлением | LIVE приоритетен, часовая запись не перебивает эфир |
| 7 | Смена утверждённого слота во время записи | Вставка обрывается и управление переходит сетке |
| 8 | Отсутствует запись/не прошёл preflight | Без падения Worker, эфир продолжает прежний источник |
| 9 | Перезапуск Worker после записи | Не более одной записи за календарный час |
| 10 | Сайт и Windows Radio Agent | Слышат один и тот же PCM->MP3, без коротких посторонних фрагментов |

## Сбор журнала

```bash
sudo journalctl -u mediaraf-radio-playout.service \
  --since "15 minutes ago" --no-pager \
  | grep -E 'RADIO_HOURLY_|RADIO_CROSSFADE|RADIO_SOURCE_BOUNDARY|RADIO_SLOT_END_MISMATCH|RADIO_REVERSE_AUTHORITY' \
  > /tmp/politech-hourly-check.log
```

Сохранить аудиозапись **сразу до и после XX:00**, а также вывести `git log -1 --format='%h %s'` и настройки обеих переменных **без раскрытия секретов**.

### Минимальные условия приёмки

- Ни одна запись не дублируется в одном часе.
- Нет тишины/клика/обрезка от старой второй деки на границах fade.
- Начало и конец утверждённой передачи не сдвигаются.
- Следующая песня стартует с нулевого offset.
- LIVE безусловно приоритетен.
- Для пропуска объявления указан объяснимый `reason`.
- Тесты проходят, журналы и аудио проверены человеком.

Если хотя бы одна проверка не выполняется, возвращать флаги в false и сохранять журнал.
