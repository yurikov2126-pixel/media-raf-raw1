# Radio 2.0 — нативный приём WebRTC на macOS (пилот)

## Что добавлено
- В macOS GUI блок «Прямой эфир с телефона · WebRTC»: запуск/остановка сетевого приёмника, журнал соединения.
- Отдельное подключение Socket.IO к `/radio-device` по токену **радиокомпьютера**, вместо пользовательского JWT; сервер разрешает подключение только действующим устройствам с `playbackAllowed=true`.
- WebRTC audio-поток поступает непосредственно в `sounddevice`/PortAudio через декодер aiortc/PyAV на **локальный аудиовыход Mac**.
- Поток по-прежнему идёт между устройствами (WebRTC/STUN), а не через серверные аудиофайлы. Запись прямого эфира не ведётся.
- Запуск вручную, не автоматическое прерывание плейлиста; если запущен пилот расписания, GUI требует сначала его остановить.

## macOS: установка зависимостей
На Mac уже должны работать Python 3.11+, Tkinter, и имеющийся графический Radio Agent.

Откройте Terminal в папке `radio-agent/macos`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install "aiortc>=1.9,<2" "python-socketio[client]>=5.11,<6" "sounddevice>=0.4.7,<1" "numpy>=1.26,<3"
python -c "import aiortc, socketio, sounddevice, numpy; print('WebRTC dependencies OK')"
python gui.py
```

Важно: используй **один и тот же Python** и для установки зависимостей, и для запуска GUI. При необходимости активируй `.venv` снова.

При ошибках установки aiortc/PyAV проверь версию Python и наличие wheel для Apple Silicon/Intel; не отключай HTTPS и не устанавливай неофициальные библиотеки с сомнительных сайтов.

## Ubuntu 24.04 + aaPanel
Новых системных пакетов и миграций нет. Развернуть обычным deploy, включая обновление Node API, и перезапустить `mediaraf-api.service` штатным способом. Socket.IO должен проксироваться по WebSocket, как уже работающие чаты.

## Проверка
1. В админке «Радио → Оборудование» зарегистрировать Mac (отдельный токен) и разрешить тестовое воспроизведение.
2. На Mac открыть GUI, проверить связь по токену.
3. Подключить только наушники. Остановить локальный пилот расписания. Нажать «Принимать прямой эфир».
4. На телефоне открыть «Радио → Эфирная студия» под ADMIN, нажать «Начать эфир с микрофона».
5. Проверить слышимость и завершение с телефона, а также «Остановить приём» на Mac.
6. Убедиться, что отозванный токен не позволяет установить **новое соединение**. Уже установленная сессия требует локальной остановки до добавления полноценного принудительного разрыва.
7. Протестировать обе сети (одна Wi-Fi и мобильная); за некоторыми NAT без TURN звук может не доходить.
8. Запустить Python-синтаксические проверки и GUI на реальном Mac до merge.

## Ограничения
- Это **пилот**, не готовая система вещания для усилителя или обязательного оповещения.
- Сейчас только один ведущий и один приёмник.
- Для устойчивой связи за NAT необходим собственный TURN-сервер, а для production — удалённый STOP, мониторинг потери звука, журнал сессий, устойчивое переключение источников, безопасный offline-режим.
- Не подключайте AA-300/ESP32 или общую акустическую сеть. Доступ STUDENT не предоставляется.
