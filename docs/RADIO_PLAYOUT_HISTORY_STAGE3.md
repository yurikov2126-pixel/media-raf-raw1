# Radio 2.0 — журнал фактически сгенерированного эфира (этап 3)

Серверный Radio Worker записывает событие после того, как декодированный PCM фактически передан на вход единого MP3-энкодера. Событие содержит ID/название трека, режим SCHEDULED/AUTO_DJ, время начала и количество сгенерированных миллисекунд. Меньше одной секунды PCM не считается подтверждённым воспроизведением. История ограничена 250 событиями и хранится в существующей таблице Setting (ключ `radio_playout_history_v1`). Администратору доступны последние 50 записей через Радио → Главная → История серверного эфира. Проверки API доступны только ADMIN.

**Важно:** запись доказывает генерацию PCM сервером, но не получение MP3 клиентом и не физическую слышимость. При Crossfade пока записывается основная дорожка (второй одновременно звучащий трек не регистрируется отдельным событием). При принудительном завершении Worker финальное событие может не успеть сохраниться. Это ограниченный журнал этапа 3, не юридически достоверный эфирный лог.

История и `recentlyPlayed()` подготавливают отдельный этап защиты от повторов **по минутам**. Новые временные ограничения в текущем PR намеренно не включены: нельзя на лету отфильтровывать композиции из детерминированного курсора, не нарушив непрерывность уже начатого трека и Crossfade. Следующий этап согласует выбор только на границе трека.
