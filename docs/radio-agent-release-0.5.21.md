# Windows Radio Agent 0.5.21 — production interface cleanup

Удалены все видимые устаревшие переключатели и средства локального лабораторного МЧС-пилота из вкладки «Эфир»: изолированный приём Android-событий, синтетические испытания GPIO13, локальные WAV-файлы, ручные тестовые ON/OFF, одиночное учебное событие, кнопки учебного звука и тестовый флажок «только наушники».

## Новое поведение

Нажатие «Запустить агент» требует только корректного URL HTTPS, токена радиокомпьютера и доступного VLC, затем запускает **основной** поток. Production MCHS поступает через защищённый основной Radio Worker и обработку Agent, а не через локальные тестовые кнопки. Никакой тестовый режим нельзя случайно выбрать в GUI.

Параметры ESP32 и включение питания остаются под отдельным локальным аппаратным допуском, проверкой API /agent/amplifier-intent, серверной политикой AUTO/MANUAL, зарегистрированным IP, подписанной арендой и watchdog. Существующие настройки, DPAPI и обновления сохраняются.

Обновлена версия приложения до **0.5.21**; после squash merge в main workflow Windows Radio Agent EXE соберёт официальный GitHub Release radio-agent-v0.5.21, прикрепит MediaRafRaw-RadioAgent.exe и проверит SHA256. Это не следует считать опубликованным до успешной загрузки артефакта в Release.

## Границы

Лабораторные вспомогательные Python-модули могут оставаться в исходной кодовой базе для обратной совместимости тестов CI, но GUI больше не предлагает их и не запускает. Изменение интерфейса **не доказывает**, что реальный усилитель AA-300 включится при тревоге. Не включайте наугад дополнительную задержку оповещения: аппаратный тракт требует отдельной проверки без ложного объявления тревоги.
