# МЧС: серверный журнал, этап 2

Этот PR подготавливает PostgreSQL для будущего сбора фактических уведомлений.

- Миграция добавляет `SafetyMchsEvent`: `source + sourceEventId` уникальны, есть время получения и события, источник, название, полный текст, район, канал Android, тип и явный флаг `verified`, по умолчанию **false**. `raw` предусмотрен для будущего безопасного ingestion без отображения через API.
- `SafetyMchsHealth` хранит последнее наблюдение и состояние listener/push. Пока таблица не пополняется, соединение честно показывает `NOT_CONFIGURED`.
- `GET /api/safety/dashboard` (роль `safety.view`) выдаёт максимум 50 записей; `GET /api/safety/events?limit=1..100` — ограниченную выборку. Обе операции требуют авторизации.
- Вкладка админки и пульт показывают события и предупреждают о неподключённом источнике.
- **Запись через сеть ещё не реализована.** Без реального Android ни журнал, ни heartbeat не должны заполняться фиктивными событиями.
- Ни одного endpoint запуска радио / громкоговорителей. `enabled=true` и `testMode=false` всё ещё запрещены на сервере.
