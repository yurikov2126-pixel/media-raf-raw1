# Radio 2.0 — обработка звука, этап 2.1

Первый безопасный этап обработки звука для **единого серверного playout**.

## Возможности
- Отдельные настройки администратора в разделе Радио → Главная.
- Однопроходный FFmpeg `loudnorm` с целью -16 LUFS и true peak -1.5 dBTP.
- `alimiter` для сдерживания пиков.
- Опциональные короткие fade-in/fade-out: 100/250/500 мс.
- Оригинальные файлы не изменяются. Источники проходят через прежний PCM→MP3 конвейер.
- По умолчанию **полный bypass**: все фильтры выключены. Настройки применяются при запуске следующего файла.

## Ограничения
Это пока **не настоящий crossfade**, потому что он требует двух одновременно декодируемых треков и сохранения жесткого старта передач. Не реализованы Cue In/Out, предварительный анализ всей аудиотеки, двухпроходное измерение LUFS, waveform и независимое аппаратное усиление. Однопроходная нормализация может давать задержку: перед её включением обязательно проверять границы расписания и начало живого эфира.

## QA
1. CI: server Vitest, frontend Vite build, `node --check server/workers/radioPlayout.js`.
2. Проверить, что с `enabled=false` звук идентичен прежней цепочке.
3. Проверить -16 LUFS/лимитер на записях разного уровня только в наушниках.
4. Проверить короткие fade, старт запланированной передачи и переключение Auto-DJ → расписание.
5. Проверить включение/отключение из админки и отдельный restart Worker при выкладке новой версии кода.

Без автоматического изменения физических выходов, Windows Agent, PA, ESP32 или реле.
