# Radio 2.0 · Этап 3 · Строгая событийная очередь

**Зависимость:** PR создан от ветки PR #412 (`feature/radio-playout-history-412`), куда ранее уже был объединён PR #413. Сначала слить #412 в main, затем поменять base данного PR на main и перепроверить CI.

Новая опция `Строго соблюдать паузу повторов` в Ротации Авто-DJ включается **только вручную** при ненулевом cooldownMinutes. Исходное поведение полностью сохранено.

В строгом режиме серверный Worker выбирает один целый трек после завершения предыдущего декодирования, используя журнал PCM и отсеивая записи, чьё начало зафиксировано в последние N минут. При равном приоритете порядок стабилен. Запланированные передачи приоритетны, а конечный срок декодирования ограничен началом следующей передачи и границей московского периода.

**Ограничения и безопасность:** если все треки недавно звучали, строгий режим выберет ожидание/тишину вместо досрочного повтора. Для небольших плейлистов это ожидаемый компромисс; такой режим нельзя включать в продакшене без достаточной библиотеки. В строгом режиме **Crossfade пока не применяется**, потому что смешивание двух треков потребует регистрации обеих дорожек и согласования с событийной очередью. После рестарта порядок может измениться исходя из сохранённой истории. Журнал подтверждает PCM, не физическую доставку звука.

**Тестирование:** проверить запуск/отключение, истечение 15/30/60-минутного интервала, ожидание при недоступных треках, переход к эфиру по расписанию, перезапуск Worker, одинаковый исполнитель/разные треки. Только наушники, без PA/усилителя/реле/ESP32. После merge серверный Worker перезапускать отдельно.
