# Радио: почему недоступна кнопка «В эфир»

Экран «Расширенная проверка переключений» — историческая DRY_RUN симуляция. Её сообщение `AUTHORITY_OR_WORKER_UNAVAILABLE` (в новой версии `DRY_RUN_DEPENDENCY_UNAVAILABLE`) означает невозможность выполнить **этот диагностический** сценарий. Оно не является подтверждением запрета или разрешения публичного LIVE.

Для реального «В эфир» должны одновременно выполняться:
1. Текущий пользователь назначен ведущим студии (ADMIN).
2. `RADIO_PUBLIC_LIVE_ENABLED=true` в API.
3. `RADIO_PUBLIC_LIVE_ENABLED=true` и `RADIO_LIVE_PCM_INTAKE_ENABLED=true` в Worker.
4. Действующий Opus-uplink отправляет звук, FFmpeg/PCM gateway работает и Worker получает кадры.
5. Сервер проверяет актуальную сессию, наличие буферизованного PCM и отсутствие утверждённой передачи по расписанию.

Новое состояние Studio health раздельно показывает разрешение на API, Worker, доступность Worker и работу декодера. Кнопка остаётся неактивной при отсутствии обязательных условий и выводит их текстом, вместо неясного предупреждения.

Запускать `RADIO_PUBLIC_LIVE_ENABLED` в production без контролируемого теста нельзя: это настоящий публичный MP3, а не приватный монитор. Сам PR не меняет флаги, PCM маршрутизацию и эфирный аудиопроцесс.

**Проверка**: подключить ведущего, запустить Opus, дождаться подтверждения Worker, убедиться в явном статусе каждого условия. Только затем контролируемо активировать LIVE при отсутствии передачи по расписанию и слушать публичный поток на втором устройстве. При неудаче использовать «Завершить эфир» и логи Worker. Никакая диагностика dry-run не является обязательным шагом для такого теста.
