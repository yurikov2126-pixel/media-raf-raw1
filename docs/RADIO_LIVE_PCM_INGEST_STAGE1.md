# Radio 2.0 — изолированный PCM-вход прямого эфира

Этап подготовки серверного приёма аудио ведущего. По умолчанию `RADIO_LIVE_PCM_INTAKE_ENABLED` выключен. Когда он включён, отдельный серверный Worker принимает **только** внутренние HTTP POST `/live-pcm/ingest` с `Content-Type: application/octet-stream`, известной длиной 4–19200 байт, кратной четырём. Формат: 48000 Hz, signed 16-bit little-endian, stereo, interleaved. Один POST содержит не более 100 мс аудио. Для запроса используется общий секрет Worker в заголовке `x-radio-worker-secret`. Worker должен слушать только loopback: внешний nginx-маршрут для ingest создавать нельзя.

Хранение ограничено двумя секундами PCM, при переполнении удаляются самые старые чанки. GET `/live-pcm/status` сообщает число фреймов, буфер, потери, свежесть входа и `connectedToEncoder:false`. Данные только принимаются в память; **никакого звукового переключения, подачи на MP3-энкодер или микрофонного захвата не выполняется**. Существующий WebRTC-прослушиватель не интегрирован с ingest.

Реальное подключение потребует авторизованного media gateway/transcoder, корректной ресемплизации Opus/WebRTC в PCM, проверки потери связи и приоритета расписания, очистки буфера при смене ведущего, защиты от воспроизведения старых данных и отдельного согласия на включение. Предварительную проверку можно проводить только на изолированном Worker через наушники. Не подключать школьные усилители, PA, ESP32 или реле.
