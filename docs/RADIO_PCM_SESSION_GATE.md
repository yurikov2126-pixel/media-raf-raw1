# Radio 2.0 — сессии PCM-входа (этап подготовки WebRTC → PCM)

В Worker появился одноисточниковый session gate перед внутренним PCM-входом. Доступ только к loopback Worker с существующим заголовком `x-radio-worker-secret`. Настройка `RADIO_LIVE_PCM_INTAKE_ENABLED=true` необходима для создания сессий; по умолчанию режим выключен.

Только доверенный внутренний media gateway должен отправлять `POST /live-pcm/session` с заголовком `x-radio-session-owner` и получать одноразовый `sessionToken`. Последующие PCM-пакеты в `POST /live-pcm/ingest` требуют `x-radio-session-token`; по умолчанию срок отсутствия успешных пакетов — 15 секунд. `DELETE /live-pcm/session` с токеном завершает сессию. Статус доступен через `GET /live-pcm/status`. Токены никогда не возвращаются в статусе. Одновременно активна только одна сессия; при смене источника буфер очищается.

**Важная граница:** серверный WebRTC/Opus gateway здесь **не реализован**. На момент этого этапа код лишь умеет авторизовать внутреннего поставщика уже преобразованного PCM. Никакой микрофон не включается и PCM не подключается к общему энкодеру/эфиру. У владельца сессии нет самостоятельного права на звук в публичном потоке. Нет внешнего nginx-проксирования этих эндпоинтов.

Далее: серверный доверенный Opus→PCM media gateway с аутентификацией роли ведущего, правами, lifecycle, heartbeat, расписанием и тестами непрерывности. До этого — не направлять живой звук в рабочий эфир и не подключать PA, усилитель, ESP32 или реле. Тестировать только через наушники на изолированной установке.
