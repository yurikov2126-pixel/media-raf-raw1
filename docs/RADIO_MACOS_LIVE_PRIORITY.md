# Радио 2.0 — приоритет прямого эфира над плейлистами (Mac Pilot)

Этот этап объединяет два **тестовых** источника звука на Mac: запланированный VLC-плейлист и удалённую речь через WebRTC. Никакого управления AA-300, ESP32, реле и аварийным оповещением нет.

## Логика
- В графическом Mac Agent администратор отдельно включает **«Включить тестовое воспроизведение»** (по расписанию) и **«Принимать прямой эфир»** (постоянный WebRTC-приёмник).
- Когда WebRTC сообщает `LISTENING` (приёмник закреплён за ведущим) или `AUDIO_START`, GUI создаёт локальный файл `~/Library/Application Support/MediaRafRadioAgent/live-priority.pause`.
- `pilot_playout.py` проверяет этот файл в основном цикле и во время воспроизведения VLC. Во время эфира он **не начинает** новые записи, а уже запущенный VLC останавливает.
- При `ENDED`, `SIGNAL_LOST` либо прекращении процесса приёмника GUI снимает паузу; проигрыватель продолжает следить за расписанием. Он **не** возобновляет прерванную запись с той же позиции и **не** доигрывает пропущенные слоты — они помечаются использованными в `played.json`. Это осознанное ограничение пилота.
- Кнопка **«Остановить приём»** также снимает признак приоритета.

## macOS: установка
Изменения только в `radio-agent/macos/gui.py` и `radio-agent/macos/pilot_playout.py`; обновить их из PR, не изменяя локальный токен и кэш. Использовать существующее Python virtualenv (aiortc, sounddevice, python-socketio[asyncio_client], aiohttp, numpy) и VLC в /Applications.

```bash
cd radio-agent/macos
source .venv/bin/activate
python -m py_compile gui.py pilot_playout.py webrtc_receiver.py
python gui.py
```

## Проверка только на наушниках
1. Устройство должно быть в режиме PILOT в админке; Mac подключён по своему токену.
2. В GUI включить **оба** режима: расписание и приём прямого эфира. При необходимости предварительно создать короткую будущую передачу.
3. Сначала убедиться, что VLC воспроизводит запись. На телефоне под ADMIN включить микрофон и открыть эфир.
4. Проверить, что VLC остановился и слышна речь с телефона **без одновременного звучания двух источников**.
5. Завершить эфир. Проверить отсутствие звука WebRTC и возобновление ожидания нового слота по расписанию.
6. Повторить цикл 3 раза, затем симулировать обрыв Wi-Fi. Убедиться, что приёмник не завис, а локальный приоритет снимается.
7. Закрыть GUI и проверить, что процессы VLC и WebRTC остановлены.

## Ограничения перед подключением колледжа
- Это **не** полноценный эфирный микшер: приоритет определяется сообщениями локального приложения, а не центральным аппаратным контроллером.
- Если GUI аварийно завершится во время эфира, файл паузы может остаться; **не использовать без оператора** до появления watchdog и арбитра источников.
- Если эфир заканчивается посередине программы, доигрывание с позиции **не реализовано**.
- За NAT в мобильных сетях требуется TURN; STUN не обеспечивает гарантированное подключение.
- Колледжную трансляционную сеть/усилитель подключать нельзя до испытания fail-safe, отдельного аварийного приоритета и устойчивости.

## Ubuntu 24.04 + aaPanel и Windows
Изменений сервера нет; новых системных пакетов, npm/pip-зависимостей сервера, миграций и настроек aaPanel нет. Windows Agent не изменён и продолжает прежнюю работу.
