# Radio 2.0 — корректный учёт двух источников Crossfade

## Зачем этот PR
При действующем Auto-DJ Crossfade серверный Worker выводит в общий MP3-энкодер микс из двух файлов, но прежний журнал учитывал только первый файл. Новый код записывает оба source ID, если Worker действительно выдал не менее 1 секунды PCM.

Журнал событий содержит `mixed: true` для источников перекрытия. У обоих событий одинаковый интервал сгенерированного **смешанного** PCM — **не следует суммировать их длительности как независимые секунды эфира**. Не подтверждает доставку MP3 приёмнику или физическую слышимость.

Новый учёт распространяется на существующий time-based Crossfade. **Crossfade строгой событийной очереди пока не включается**: для этого необходимо продумать резервирование двух следующих записей до начала перекрытия и обновление cooldown при запуске смешивания. Иначе строгий запрет повторов может нарушиться.

## Безопасный порядок внедрения
1. Объединить PR #412 в `main` (в него уже вошли PR #413, #414 и #415), убедиться, что он проходит CI.
2. Перенаправить этот PR на `main`, повторно пройти CI и объединить.
3. Перезапустить серверный Radio Worker отдельно от API.
4. Только через наушники проверить Crossfade 0 и 1–3 секунды, журнал обоих треков, отсутствие ложной записи при ошибке декодера и границу сетки.
5. Не подключать школьную PA, усилитель, ESP32 или реле. Windows Agent не изменяется.
