# PR #1018 — сопоставление решений Windows Agent и GPIO13 OFF

## Цель
Ранее админка показывала отдельные записи ESP32 и Windows Agent. Причину кратких циклов OFF→ON приходилось сопоставлять вручную. Теперь каждый **наблюдавшийся** переход `FIRMWARE_GPIO_OFF` в пределах последних 10 минут сопровождается указанием ближайших разрешённых диагностических свидетельств Agent.

Обрабатываются не более 12 последних firmware OFF из уже ограниченной истории (до 70 событий за последние 10 минут), причём **только от выбранного рабочего ESP32 и Reporter Windows Agent**:
- `AGENT_POWER_POWER_COMMAND` с `permit:false` — рядом есть подтверждение команды OFF;
- `AGENT_POWER_INTENT_RESPONSE` с `permit:false` — рядом есть отказ центральной политики;
- `AGENT_POWER_INTENT_ERROR` или `AGENT_POWER_POWER_ERROR` — рядом есть ошибка связи/команды;
- иначе — убедительного подтверждения Agent нет.

Сопоставление выполняется в окне ±15 секунд от времени наблюдения сервером. Успешный запрос ON не приравнивается к OFF; записи другого ESP32 или Agent игнорируются. При совпадениях приоритет отдаётся подтверждению OFF, а не произвольному сообщению.

## Как использовать
1. В админке «Экстренное оповещение → Тракт оповещения» выбрать рабочий Windows Agent (эта настройка уже появилась в PR #1016).
2. Убедиться, что новая ESP32-прошивка реально передаёт `relayTransitionHistory`, а Windows Agent передаёт `agentPowerEvidence`.
3. Под «Историей управления усилителем» изучить блок «Сопоставление OFF с решениями Windows Agent». Для каждого события показаны код firmware, соседний факт Agent и примерный интервал.
4. При кратком OFF→ON **с отключённой силовой нагрузкой** смотреть исходную хронологию для возможных объяснений: например `SIGNED_PERMIT_FALSE` + `AGENT_POWER_POWER_COMMAND permit:false`, либо `POWER_LEASE_EXPIRED` + ошибки чтения серверного intent.

## Ограничения
- ESP32 сохраняет `uptimeMs`, но сервер сейчас назначает событию **время получения опроса**. Поэтому близость сообщений не доказывает причинную связь или порядок реальных переключений.
- Clock Windows Agent, задержки сети, пакеты, перезагрузки ESP32 и ring overflow могут искажать совпадение. `approximateGapMs` — расстояние между отметками наблюдений, не задержка физического реле.
- Подтверждённый `POWER_COMMAND` — подтверждение команды по API ESP32, **не** независимая фиксация 220 В на AA-300 и не доказательство звука.
- После 10 минут или переполнения ограниченного журнала более старые события перестают учитываться.
- PR не меняет HMAC, lease, watchdog, управление GPIO13, Radio Worker, автоматический старт МЧС или аварийный STOP.

Для решения вопроса реальных кратковременных отключений нужна аппаратная проверка с безопасно изолированной силовой цепью и проверкой согласования часов.
