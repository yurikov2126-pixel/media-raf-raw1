# Разбор реальной тревоги 12 ноября 2026, 13:51 МСК

Сессия `cmwdfi8f2040jjxnsnpt8pr73` для `MISSILE_DANGER` была принята Radio Worker в 13:52:34 МСК, проиграла один полный ALARM и завершила PCM clock в 13:53:17 без gap. Терминальный журнал зафиксировал в 13:53:22:

```json
{"eventId":"cmwdfi8f2040jjxnsnpt8pr73","eventType":"MISSILE_DANGER","repeats":1,"completedRepeats":1,"preemptAcknowledged":true,"naturalCompletion":true,"programRestored":false,"failure":"SILENT_PROGRAM_RETURN_TIMEOUT","phase":"FAILED"}
```

Пользователь подтвердил, что ALARM прозвучал один раз, и что в этот момент не было назначенных задач ни в сетке, ни в AutoDJ.

### Исправление

- После естественного завершения тревоги Radio Worker учитывает доказуемый режим `SILENCE` из ветки `current()` (отсутствует аудиоресурс) и подтверждает успешный возврат в простой вместо ожидания несуществующей музыки.
- Терминальная сессия маркируется `COMPLETE`, `naturalCompletion:true`, `programRestored:false`, `idleAfterAlert:true`. Не утверждаем, что какая-либо обычная программа начала играть.
- Если обычный источник выбран и выдаёт тишину, сохраняется прежняя защитная ошибка `SILENT_PROGRAM_RETURN_TIMEOUT`, чтобы не скрыть реальные сбои.
- Старые `FAILED` записи нельзя и не следует задним числом менять. Новый код применяется к будущим тревогам. Изменений в воспроизведении самого ALARM, усилителе, Windows Agent и API входящих Android событий нет.
- Испытания: натуральный финиш → подтверждённый idle; обычный ненулевой PCM; ошибочная тишина; успешная запись `COMPLETE` в журнал, перезапуск журнала, запуск последующего `ALL_CLEAR`.

### Развёртывание

После прохождения CI и слияния PR — деплой в production по действующему процессу. Не выполнять перезапуск Radio Worker во время реального экстренного оповещения. Не вызывать синтетический START в основном эфире для валидации.
