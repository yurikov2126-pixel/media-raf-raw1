# МЧС #964 — проверка готовности реального аудиотракта

Этот этап добавляет **только читающий** контроль состояния действующих Radio Worker
и Windows Agent перед отдельным акустическим испытанием в наушниках.

## Административный запрос

`GET /api/safety/missile-live-audio-preflight` (роль ADMIN)

Ответ: `softwareChainObserved`, `workerMode`, `agentSource`,
`agentPlayback`, `holds`. Положительный результат требует:

- Worker сообщает поддерживаемый источник программы без `lastError`;
- учебный PCM overlay не активен и возвращён в `NORMAL_PROGRAM`;
- задан `MCHS_AGENT_LAB_DEVICE_ID`;
- для этого устройства в базе есть свежая (< 20 секунд) телеметрия
  `source=CENTRAL`, `playback=PLAYING`, `lastPacketAgeMs <= 5000`.

Полученная телеметрия **не доказывает**, что звук слышен в наушниках.
Endpoint не принимает команды START/STOP и никогда не выдаёт
разрешения на ALARM (`mayStartAlarm:false`), публичную трансляцию
или PA. Он не проверяет физическое отсоединение кабеля к усилителю.

## Порядок испытания без риска для громкоговорителей

1. На радиокомпьютере физически отключить все выходы к усилителю AA-300
   и альтернативные линии PA; ESP32 не использовать.
2. Подключить наушники, запустить штатный Windows Agent. Проверить
   слышимость обычной музыки вручную.
3. Убедиться, что в окружении API задан ID именно этого Agent в
   `MCHS_AGENT_LAB_DEVICE_ID`. Не публиковать ID вместе с секретами.
4. Под учётной записью ADMIN вызвать указанный GET и проверить
   `softwareChainObserved:true`, `holds:[]`.
5. Для отдельного локального испытания доступен ранее реализованный
   `radio-agent/windows/mchs_headphones_trial.py` с инструкцией
   `radio-agent/windows/MCHS_HEADPHONES_TRIAL.md`.
   Он проверяет локальное воспроизведение WAV, **не реальный общий
   двухканальный ALARM**.
6. После локальной проверки повторить GET и убедиться, что Agent снова
   получает свежий `CENTRAL` звук. Проверка возврата после конкретной
   event-bound ALARM-сессии — отдельный `missile-station-resume`.

## Что остаётся неготовым

Worker `/mchs-training-stream` использует общий радиомикшер. Поэтому
соединять его с настоящим START автоматически на работающей станции
нельзя без отдельного физически/логически изолированного тракта.

Данный PR **не реализует** реальный полный сценарий ALARM →
оба выхода → отбой; он предоставляет безопасную диагностику
существующих служб перед будущим контролируемым испытанием.
