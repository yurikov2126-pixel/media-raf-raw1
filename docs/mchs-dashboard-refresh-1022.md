# PR #1022 — исправление панели основного тракта по реальному скриншоту

## Обнаруженные ошибки
1. В `MchsTransportStatus.jsx` периодический опрос (каждые 15 секунд) и обновление после сохранения Agent получали объект `a` из `GET /missile-production-auto-readiness`, но не вызывали `setProduction(a)`. Поэтому при первом открытии все 13 проверок отсутствовали, число каналов отображалось как «—», хотя другие карточки обновлялись.
2. Кнопка «Сохранить» блокировалась, если выбранный Agent совпадал с уже отображаемым ID, **даже когда привязка была `LEGACY_LAB_FALLBACK`**. Выбранный Studio нельзя было повысить до полноценной `ADMIN_BOUND` без бессмысленного выбора другого устройства.
3. При недоступном статусе MCHS Worker интерфейс показывал только «Нет связи / UNKNOWN», скрывая `WORKER_NOT_CONFIGURED`, `COORDINATOR_DISABLED`, `WORKER_UNAVAILABLE` или другой код, возвращённый служебным транспортом.

## Изменения
- Периодический опрос и сохранение привязки обновляют production-проверки так же, как кнопка «Обновить»;
- при отсутствии первого ответа показывается «Получаем результаты проверок», а при наличии — число непрошедших проверок;
- разрешено нажимать «Сохранить» для выбранного устройства с `LEGACY_LAB_FALLBACK`, если серверная переменная окружения не блокирует админский выбор;
- причина отказа служебного Worker STATUS показывается рядом со статусом Worker, не смешивается с ошибками аудиоплеера и не воспринимается как доказательство неисправности всей станции;
- добавлены серверные тесты передачи технической причины отказа.

## Как проверить после объединения
1. Открыть «Экстренное оповещение → Тракт оповещения». В блоке готовности должны появиться все 13 строк с результатом Да/Нет; при периодическом обновлении они остаются на экране.
2. Для уже отображённого `Studio`, когда написано «лабораторная привязка», нажать **Сохранить**. После успешного ответа `ADMIN_BOUND` предупреждение должно исчезнуть. Если настройка закреплена переменной `MCHS_MAIN_STATION_AGENT_DEVICE_ID`, требуется менять именно переменную, а кнопка намеренно заблокирована.
3. Если Worker по-прежнему «Нет связи», прочитать код в карточке. Это диагностика `GET /mchs-station-session`, а не измерение самого звукового потока.

## Проверка службы Radio Worker на сервере
Только чтение, без изменения конфигурации:
```bash
sudo systemctl status mediaraf-radio-playout.service --no-pager
sudo journalctl -u mediaraf-radio-playout.service --since "20 minutes ago" --no-pager | tail -100
sudo ss -ltnp | grep ':4105'
sudo systemctl status mediaraf-api.service --no-pager
```
Не вставляйте секрет Worker (`RADIO_PLAYOUT_SECRET`) в переписку и не отправляйте содержимое `/etc/m...env` целиком. Если в API и Worker разные значения секретов или не настроены окружения, служебный endpoint может остаться недоступным при работающем обычном звуке.

**Не включайте три флага реального автоматического ALARM только ради исчезновения красных строк** до проверки канала приёма, аудиофайлов и фактического тракта.
