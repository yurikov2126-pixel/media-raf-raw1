# МЧС — терминальная история PCM (PR #1003)

Короткие сообщения могли закончиться между 15-секундными опросами API и не попасть в журнал #1002. Worker теперь сообщает в защищённом GET `/mchs-station-session` последние 128 терминальных результатов `COMPLETE` и `FAILED` существующего lifecycle. Сервер обрабатывает каждый терминальный eventId перед текущим снимком и сохраняет подтверждение в PostgreSQL. Успешный COMPLETE требует подтверждения подмены PCM, полного числа повторов и возврата ненулевого PCM программы.

Worker-хранилище пока **в памяти**, поэтому после перезапуска Worker ещё не опрошенные terminal events теряются. Это не постоянный журнал событий и не доказательство слышимости в браузере/PA. Следующий этап — отдельный persistent Worker event outbox с повторной доставкой. Все три флага автоматического live START остаются выключенными, ESP32 не меняется.
