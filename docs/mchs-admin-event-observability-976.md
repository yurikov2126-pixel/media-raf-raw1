# МЧС #976 — результаты Windows Agent в существующем разделе «Экстренное оповещение»

## Изменения

Вкладка **Админка → Экстренное оповещение → Уведомления** теперь
отображает **выполнение учебных оповещений — Windows Agent** над уже
существующим журналом сообщений МЧС. Не создаётся новая вкладка, второй
журнал технических инцидентов, аварийная кнопка START/STOP или отдельная
система ручного подтверждения.

Карточки результатов привязаны к `eventId` из серверной команды Agent
и показывают: опасность/отбой, успешное/ошибочное исполнение, число
выполненных повторов, естественное окончание учебного WAV, подтверждение
возврата центральных пакетов, время получения и читаемую причину сбоя.
Карточки адаптированы для мобильной ширины и светлой/тёмной темы.

## Источник данных и границы

PR #975 записывал в `prisma.setting` только **последний** результат.
Теперь device-auth маршрут `POST /api/radio-agent/agent/mchs-event-execution-observation`
принимает прежний проверенный payload и сохраняет отдельную **ограниченную
историю 50 последних различных eventId**. Повторный отчёт по тому же
`eventId` заменяет прежний, сохранение идёт транзакционно.

Read-only admin API:
`GET /api/radio-agent/mchs-agent-event-execution-observations`.
Он работает только для администратора и возвращает последние результаты
от привязанного `MCHS_AGENT_LAB_DEVICE_ID`. Токены и сырые пути WAV
в UI не выводятся.

Это **журнал локальных учебных результатов**, а не подтверждение
того, что тревога прозвучала в здании. Во всех ответах:
`localProcessObservationOnly:true`,
`physicalPaOutputVerified:false`,
`publicPlaybackAuthorized:false`.

Существующий список Android сообщений остаётся прежним. Объединять
записи по похожему тексту или времени нельзя: в текущем протоколе
нет подтверждённого общего ID между Android-уведомлением и аудиособытием.
Поэтому учебные результаты показываются **в том же разделе**, но
не приписываются произвольному Android-сообщению.

## Проверка

1. Объединить PR #976 и дождаться успешного CI/deploy API и клиента.
2. Открыть админку: **Экстренное оповещение → Уведомления**.
3. При отсутствии записей виден честный статус «отчётов пока нет».
   Старые данные #975 остаются в прежнем поле последнего результата,
   но в новую историю автоматически не переносятся.
4. Пройти учебный event-bound цикл Windows Agent из #974/#975
   (в наушниках, AA-300/PA физически отключены), затем нажать
   **Обновить**. Карточка показывает `completedRepeats/expectedRepeats`,
   завершение и возвращение центральных пакетов.
5. На телефоне убедиться, что карточки не обрезаются и не требуют
   горизонтального скролла; в тёмной теме тексты читаемы.
6. Проверить, что кнопок запуска/остановки тревоги здесь нет.

Серверные тесты `server/tests/mchsExecutionObservationHistory.test.js`
проверяют историю, ограничение памяти, повторные результаты, повреждённые
данные и то, что PA никогда не объявляется подтверждённой.
