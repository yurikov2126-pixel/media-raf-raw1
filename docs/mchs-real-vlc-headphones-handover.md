# МЧС #967 — проверка реальных VLC-процессов: музыка → учебный WAV → музыка

Режим запускается **локально оператором** на Windows с отсоединённым
физическим кабелем к AA-300 и отсутствием других выходов в PA.
Используется существующий авторизованный 2-секундный WAV, а для
музыкальной программы — указанный оператором *локальный файл*.
Скрипт запускает собственные VLC-процессы: музыка, учебные повторы,
новый процесс музыки; проверяет процессы и естественное завершение.

Он **не управляет работающим Windows Radio Agent**, поэтому для
проверки отсутствия наложения звука убедитесь, что воспроизведение
других программ на испытательном выходе остановлено. Это не автоматический
переход из текущего центрального потока и не проверка возобновления
того же трека/позиции.

## Запуск в PowerShell

Заранее подготовьте локальный музыкальный файл (дольше 15 секунд)
и настройте существующий тестовый WAV endpoint, как описано в
`radio-agent/windows/MCHS_HEADPHONES_TRIAL.md`.

```powershell
cd radio-agent/windows
$env:RADIO_AGENT_TOKEN = Read-Host "Radio Agent token"
python .\mchs_vlc_handover_pilot.py --vlc "C:\Program Files\VideoLAN\VLC\vlc.exe" --program-file "C:\TestMusic\track.mp3" --repeats 4 --completion-timeout 60
Remove-Item Env:\RADIO_AGENT_TOKEN
```

После подтверждения `ISOLATED` в наушниках должна звучать музыка,
затем четыре раза учебный WAV, затем снова музыка. В отчёте ожидаются
`ok=True`, `alarm_natural_completion=True`,
`program_restored=True`. После отчёта локальный музыкальный процесс
завершается — это ожидаемая очистка процесса пилота.

## Границы

Не подключает `central_playout.py` к этому механизму, не передаёт
ALARM в общий Worker mixer, не отправляет START на Windows Agent,
не включает публичное радио или ESP32. Программное восстановление
**локальной** музыки не доказывает доставку центрального PCM-потока.
Полный путь Android → Worker + Agent → возврат остаётся отдельным этапом.
