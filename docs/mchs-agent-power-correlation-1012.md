# PR #1012 — сопоставление решений Windows Agent и командных переходов GPIO13

## Что добавлено

Windows Agent уже сохраняет локальный `power-diagnostics.log` с `INTENT_RESPONSE`, `INTENT_ERROR`, `POWER_COMMAND`, `POWER_ERROR`, `RELAY_TRANSITION`. Без этих данных невозможно проверить, произошло ли переключение GPIO13 из-за отказа сервера, собственного местного ограничения Agent или watchdog ESP32.

Добавлен модуль `radio-agent/windows/mchs_power_evidence.py`, читающий **не более 64 КиБ конца существующего журнала**. Он извлекает максимум 16 событий возрастом не старше 10 минут. Передаются только:
- hash-идентификатор строки (24 шестнадцатеричных символа);
- UTC-смещённая временная метка наблюдения Agent;
- один из пяти перечисленных типов;
- булево `permit`, допустимый HTTP-код;
- коды причины, перехода, фазы или ошибки **только** при строгом формате `[A-Z0-9_]`.

Пароли ESP32, `rr_`-токены, HTTP headers, Wi-Fi SSID, URL, произвольный текст исключены. Локальный оригинальный журнал остаётся на Windows; его содержимое целиком не отправляется. При ошибке чтения Agent возвращает пустой набор и продолжает обычную работу.

Во время существующего 15-секундного опроса ESP32 Windows Agent добавляет поле `agentPowerEvidence` в уже авторизованный `POST /api/radio-agent/agent/esp32-status`. Новый маршрут управления реле не создаётся.

Сервер перепроверяет имена и типы полей, максимальный размер пакета, возраст, hex-ID и уникальность. Записи привязываются к зарегистрированному Agent и ESP32, вносятся в ограниченный журнал `mchs_esp32_transition_evidence_v1` и отображаются в административной вкладке рядом с `FIRMWARE_GPIO_OFF`/`FIRMWARE_GPIO_ON`.

## Как читать результат

- `AGENT_POWER_INTENT_RESPONSE` с `permit:false` рядом с `FIRMWARE_GPIO_OFF` указывает на отказ центральной политики, но сам по себе **не доказывает причинность**.
- `AGENT_POWER_INTENT_ERROR` + `FIRMWARE_GPIO_OFF:POWER_LEASE_EXPIRED` показывает возможную цепочку «потеря разрешения → срок lease истёк», однако точность сопоставления зависит от часов Windows, сетевой задержки и опроса.
- `AGENT_POWER_POWER_ERROR` означает, что Agent не получил подтверждения команды. Не считать это подтверждением выключения усилителя.
- Без новой ESP32-прошивки из PR #1011 не будет отдельного журналирования каждого firmware GPIO-перехода; Agent-события при этом могут отображаться независимо.

## Ограничения и безопасность

Никакого включения GPIO13, команды START МЧС, изменения lease, watchdog или радиоэфира не добавлено. Наблюдение не равно независимому замеру 220 В, включению AA-300 либо звуку в коридорах.

Успешный CI проверяет корректность серверного whitelist, дедупликацию и отсутствие секретов в JavaScript/Python. Для применения изменений Windows Agent необходим новый дистрибутив/запуск версии с этим модулем; серверный PR сам по себе не обновляет уже установленный EXE. До аппаратной проверки держите силовую нагрузку отключённой.

Этот PR сделан независимо от пока открытого PR #1011; после его объединения администратор увидит в одной ленте и решения Agent, и причины каждой firmware-команды GPIO.
