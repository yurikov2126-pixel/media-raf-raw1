# Radio 2.0 — аудиодвижок 3.0: PCM staging (пилот)

## Содержание
Этот PR вводит ограниченный по памяти буфер для декодированного PCM (signed 16-bit, stereo, 48 kHz) перед подачей в уже работающий MP3-энкодер. Пакеты из FFmpeg выравниваются по 4 байтам на один стереофрейм. Неполный фрейм удерживается до следующего блока; в конце декодирования неполный хвост отбрасывается, а счётчик потерь увеличивается. Буфер ограничен 2 MiB; переполнение вызывает ошибку вместо бесконтрольного роста памяти.

Пилот активируется только при `RADIO_PCM_STAGING_ENABLED=true` в окружении **серверного** Worker и только после отдельного перезапуска Worker. По умолчанию `false`. Диагностика в health: `pcmStaging.enabled`, `processedBytes`, `droppedTailBytes`. При отсутствии опции аудиопуть остаётся прежним.

## Что НЕ реализовано
Это **выравнивание PCM**, а не запас аудио на несколько секунд и не доказанный gapless engine. Переключения между процессами FFmpeg по-прежнему могут давать паузы. Crossfade в строгой событийной очереди не активируется этим PR: для него потребуются предварительное декодирование, корректные timestamp, атомарная фиксация двух выбранных файлов и тестирование непрерывной PCM-шкалы.

## Испытания
- Проверить server lint/tests, client CI и работу Worker с опцией `false`.
- На отдельном тестовом экземпляре включить staging, прослушать переходы обычных треков, Crossfade и Cue через **наушники**; следить за `droppedTailBytes` и логами.
- Проверить точный старт запланированной передачи, ограничение памяти и выключение опции после тестов.
- Не подключать школьную PA, усилитель, ESP32, реле и не менять Windows Agent.
