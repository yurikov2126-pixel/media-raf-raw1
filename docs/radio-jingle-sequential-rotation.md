# Auto-DJ: переходы через джинглы

Исправление для публичного MP3 Worker: обычная ротация больше не пересчитывает позицию песни по текущим часам после окончания джингла. Последующая композиция выбирается последовательной очередью и начинается с настроенной Cue In (по умолчанию 0).

- Джингл **не** увеличивает индекс музыкальной очереди.
- Очередь переходит к следующему треку только после завершения декодирования текущей композиции.
- При смене плейлиста, периода ротации, состава файлов, приоритетной передаче или переключении на LIVE последовательность сбрасывается; приоритет расписания остаётся прежним.
- Не выполняется лишний запрос DSP-настроек в ветке выбора обычной музыки.

## Важно
В коде по-прежнему каждый файл проигрывается новым процессом FFmpeg, а выбор следующего аудио выполняется с запросами БД. Поэтому задержка на переходе **может оставаться**, и это исправление не является бесшовным кроссфейдом или гарантией нулевого зазора. Для полного gapless необходима предварительная подготовка PCM следующего элемента и единый непрерывный вывод при смене источника.

Проверить на публичном MP3-потоке: Auto-DJ → джингл → следующая композиция, с Cue In 0 и ненулевым, обычная и строгая ротация, приоритет утверждённой передачи и LIVE, ручное выключение джинглов. Не проверять только прогнозный плеер — слушать реальный поток.
