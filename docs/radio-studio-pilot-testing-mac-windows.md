# RADIO 3.3 — подробная инструкция по изолированному тесту звука

## Почему тест на скриншоте не запустился

Две зелёные полосы L/R свидетельствуют, что браузер видит локальный микрофон (если устройство моно, показания могут дублироваться). Надпись **«Тестовый шлюз отключён»** выдаётся API при `RADIO_BROWSER_OPUS_UPLINK_ENABLED !== 'true'`. В таком случае тестовый Opus uplink недоступен. Когда Opus разрешён, но `RADIO_BROWSER_PCM_GATEWAY_ENABLED` отключён, проверка пакетов возможна, но сервер не декодирует аудио в PCM. Окна PCM-прослушивания без работающего шлюза не работают.

**Важно**: обычная кнопка «Начать эфир с микрофона» пока создаёт браузерную роль ведущего / прямое WebRTC-подключение второго браузера; это НЕ живой публичный MP3 и не подключение к школьной акустике.

## A. Проверка без изменения сервера (ведущий)

1. Подключите RØDECaster Duo к Mac по USB, подключите наушники, не подключайте школьный усилитель, активные громкоговорители и ESP32.
2. Откройте сайт через HTTPS в актуальном Google Chrome. Для Windows — Chrome или Edge.
3. Разрешите микрофон для сайта (значок слева от адреса → разрешить). В разделе «Радио → Студия» выберите USB-устройство RØDECaster Duo. Браузер может предоставить Main Mix как моно — факт определяйте по настройкам входящего трека, а не двум графическим полоскам.
4. Произнесите короткую фразу. Если L/R изменяются, устройство работает **локально**. Если нет — откройте системные параметры звука и настройки USB-выхода RØDECaster; проверьте уровни и отключение mute.
5. Нажмите «Начать эфир с микрофона»; статус ведущего должен стать «подключён».
6. Посмотрите под карточкой источника: если указано «Opus uplink выключен на API» или «FFmpeg/PCM-шлюз выключен на API», это **серверная настройка**, которую нельзя исправить нажатием кнопки на Mac. Остановите тест и выполните раздел B.
7. При активном тестовом шлюзе нажмите «Тест передачи Opus», дождитесь подтверждения блоков и проверьте техническую диагностику, а затем приватное прослушивание. Мониторы доступны только если сервер декодирует PCM и соответствующие флаги включены.
8. После теста остановите Opus, затем «Завершить тест». Убедитесь, что микрофон закрылся. Для проверки отдельного браузерного WebRTC-слушателя откройте другой компьютер и нажмите «Принимать эфир на этом устройстве»: это другой тракт и сам по себе не проверяет PCM Worker.

## B. Что должен проверить администратор сервера (изолированный стенд!)

**Нельзя просто включить экспериментальные флаги в production на действующей школьной системе.** Нужен отдельный тестовый экземпляр API и Worker на отдельной машине или в изолированной среде с отключённым физическим аудиовыходом/усилителем. Только после оценки прав и сетевой доступности.

Проверьте на стенде:
- Node.js, FFmpeg/FFprobe: `node -v`, `ffmpeg -version`, `ffprobe -version`.
- Для API: `RADIO_BROWSER_OPUS_UPLINK_ENABLED=true` и `RADIO_BROWSER_PCM_GATEWAY_ENABLED=true`.
- Для Worker: `RADIO_PLAYOUT_ENABLED=true`, `RADIO_LIVE_PCM_INTAKE_ENABLED=true` и `RADIO_PRIVATE_PCM_PREVIEW_ENABLED=true` для односекундного WAV; `RADIO_PRIVATE_LIVE_MONITOR_ENABLED=true` — для непрерывного PCM; `RADIO_ISOLATED_MIX_OUTPUT_ENABLED=true` — для голоса с тестовой музыкой. Сам Worker может при обычном запуске также заниматься станционным MP3, поэтому **не поднимайте его с этими параметрами на production без физической и сетевой изоляции**.
- `RADIO_PLAYOUT_SECRET`: одинаковое случайное секретное значение длиной от 32 символов для API и Worker, без публикации в логах, чатах или скриншотах.
- `RADIO_PLAYOUT_PORT`: одинаковый свободный локальный порт (по умолчанию 4105); Worker слушает loopback `127.0.0.1`. Если API и Worker разнесены по хостам, существующий `workerRequest` до Worker напрямую не дойдёт. Не открывайте этот порт в интернет.
- Проверьте изолированный Worker через **локальный** защищённый health запрос/существующие команды тестового стенда, затем перезапустите оба процесса и смотрите их журналы. Изменение переменных окружения без перезапуска не применяется.

Пример **значений переменных**, не готовый production конфиг:

```dotenv
# isolated test API
RADIO_BROWSER_OPUS_UPLINK_ENABLED=true
RADIO_BROWSER_PCM_GATEWAY_ENABLED=true
RADIO_PLAYOUT_PORT=4105
RADIO_PLAYOUT_SECRET=<one-shared-random-secret-at-least-32-chars>

# isolated test Worker
RADIO_PLAYOUT_ENABLED=true
RADIO_LIVE_PCM_INTAKE_ENABLED=true
RADIO_PRIVATE_PCM_PREVIEW_ENABLED=true
RADIO_PRIVATE_LIVE_MONITOR_ENABLED=true
RADIO_ISOLATED_MIX_OUTPUT_ENABLED=true
RADIO_PLAYOUT_PORT=4105
RADIO_PLAYOUT_SECRET=<same-shared-secret>
```

Не копируйте одну секцию поверх конфигурации работающей радиостанции. Значение в угловых скобках — пример, не настоящий секрет. **Не включайте** `RADIO_ISOLATED_REAL_MUSIC_ENABLED`, пока не подготовлен отдельный валидный PCM-файл; тестовый музыкальный микс умеет использовать синтетический сигнал.

## C. Ожидаемые результаты по шагам

| Шаг | Успех | Если не получилось |
| --- | --- | --- |
| Системный USB-вход | RØDECaster виден в Mac/Windows | Кабель, порт, USB Main routing, системный доступ |
| Индикаторы L/R | Полосы двигаются при речи | Проверьте mute, фейдер и разрешение микрофона |
| «Начать эфир» | Студия назначает роль ведущего | Проверить Socket.IO, авторизацию и второго ведущего |
| «Тест передачи Opus» | «Подтверждено блоков: N» | Включить оба API-флага и Worker intake, проверить ffmpeg |
| PCM Worker | «Доступен» во время активного шлюза | Совпадение secret/port, Worker, loopback |
| Декодер | «Работает» | ffmpeg в PATH, ошибка декодирования, права |
| PCM | Данные свежие | Проверьте 250мс MediaRecorder, сетевые пакеты, Worker |
| WAV-фрагмент | Файл появляется, звук слышен | Флаг PRIVATE_PCM_PREVIEW, активная сессия, свежие кадры |
| Непрерывный PCM | Монитор запускается | PRIVATE_LIVE_MONITOR, сброс при пропуске кадров |
| Музыка + голос | Слышно тестовый микс | ISOLATED_MIX_OUTPUT, USB mix-minus |

## D. Результат диагностики и логи

Если не работает:
- Зафиксируйте, какие две надписи появились в студии (серверный шлюз, Opus), какую кнопку нажали и что ответил интерфейс.
- Запишите платформу Mac/Windows, версию Chrome/Edge, название входного USB-устройства и фактическое число каналов.
- Серверный администратор смотрит журналы **именно тестовых** API и Worker, ошибки вида `WORKER_NOT_CONFIGURED`, `WORKER_HTTP_404`, `FFMPEG_EXIT_`, `DECODER_STALLED`.
- Никогда не присылайте `RADIO_PLAYOUT_SECRET`, полные токены пользователей или приватные аудиофайлы в чат.
- Завершите тест и убедитесь, что школьный MP3/Auto-DJ и оборудование не затронуты.

Проверка «диагностики готовности» может оставаться жёлтой из-за `RADIO_TIMED_PCM_SHADOW_ENABLED` и авторитетного расписания даже когда локальный микрофон и Opus работают. Это защитный блок для переключения эфира, **не обязательно ошибка микрофона**.
