# RADIO: почему трек Windows Agent не совпадает с «Ротацией»

## Подтверждено анализом кода
1. Централизованный MP3 Worker (`server/workers/radioPlayout.js`) рассчитывает ротацию по `rotationPlan`: московский период, категории, приоритет, ограничения исполнителя, история/cooldown, cue и джинглы. При включении события по расписанию музыка уступает ему.
2. Эндпоинт `GET /radio/music-plan` до исправления возвращал **приблизительный прогноз** из `previewMusicQueue`. Он не учитывает фактически замороженный план Worker, живые часы и все события.
3. Windows Radio Agent (локальное резервное воспроизведение) использует синхронизированный список `autoDj.tracks` в порядке плейлиста, а `radio-agent/windows/standby_plan.py` выбирает песню по `nowMs % суммарной длительности`. Он **не выполняет** `rotationPlan`; локальный track может отличаться от центрального MP3. Локальное аудио нельзя надёжно установить из состояния центрального Worker.

## Изменено
- `GET /radio/music-plan` возвращает `playback` — проверенный настоящий `mode` и `trackId` центрального Worker (`/health` по защищённому loopback); track ID разрешается в название аудиофайла через БД. Если Worker недоступен, честный статус unavailable вместо ложного трека.
- Интерфейс «Ротация» показывает **фактически выбранный центральным Worker трек** отдельно от прогнозируемого списка и чётко поясняет, что резервное локальное воспроизведение Windows — независимый механизм.

## Что пока НЕ исправлено
Этот PR не заставляет локальный Windows Agent мгновенно следовать центральной ротации: это было бы ошибкой при отказе сети и могло бы прервать автономный эфир. Для синхронизации резервного плейаута нужно передавать на агент целостный авторитетный план с версиями расписания, замороженным порядком, cue, джинглами и epoch-смещениями, плюс failover fencing. Пока этого нет, резерв нельзя позиционировать как точное зеркало центрального Auto-DJ.

## Регрессия
- Worker доступен: реальный трек/источник в разделе ротации совпадает с `/health` Worker, даже если прогноз отличается.
- Worker выключен: «нет подтверждения» вместо вымышленной песни.
- При LIVE/расписании: отображается режим Worker и отсутствие музыкального trackId там, где это применимо.
- Сверить с локальным логом `LOCAL_TRACK` Windows Agent — различие до реальной синхронизации остается ожидаемым.
- Никакой код переключения MP3 и Windows Agent в этом PR не изменяется.

Безопасно для действующей станции: это только чтение Worker и представление состояния.
