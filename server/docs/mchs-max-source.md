# MAX: региональные публикации для сверки МЧС

Источник: [Тульская область](https://max.ru/tularegion71). Telegram больше не используется.

Серверный адаптер использует документированный `GET https://platform-api2.max.ru/messages?chat_id=...&count=100`; токен передаётся только в заголовке Authorization. По документации MAX бот должен быть **администратором канала**, чтобы читать сообщения по chat_id. Не следует пытаться обойти права доступа парсингом HTML.

Переменные среды API (не публиковать в Git или интерфейсе):

- `MCHS_MAX_BOT_TOKEN` — токен собственного бота MAX;
- `MCHS_MAX_CHANNEL_CHAT_ID` — числовой ID канала, доступного этому боту с административными правами.

Для государственного канала @tularegion71 у нас пока **не подтверждены административные права бота**. Пока нет договорённости с владельцами канала, источник возвращает `MAX_CHANNEL_ACCESS_NOT_CONFIGURED`; это ожидаемый, безопасный результат. Нельзя подменять его «нет тревог». Если доступа получить невозможно, нужен согласованный официальный интерфейс получения событий или другой доверенный канал.

Маршруты ADMIN: `GET /safety/missile-official-bulletins`, `GET /safety/missile-bulletin-correlation`, `POST /safety/missile-correlation-review/refresh`. Все являются *review only* и не включают сирену, Radio Worker или ESP32. Публикация MAX — дополнительное свидетельство, **не авторизация на экстренное вещание**.

Документация: https://dev.max.ru/docs-api/methods/GET/messages
